# 0001 정적 목업 UI 스택과 화면 분할

- 날짜: 2026-10-15
- 상태: 확정 (2026-10-15, UI-01 리뷰 APPROVED)
- 출처: 사용자 요청 "목 데이터 기반 정적 모바일 웹 UI로 P0 58개 화면을 구현하자. 흐름별로 브리프를 나누자."

## 배경

저장소에는 기획 문서와 목업 `beta_mock-up.html`만 있고 앱 코드는 없다. 목업은 디자인 도구에서 내보낸 번들이라 그대로 앱 코드로 쓸 수 없다. 이번 단계의 목표는 서버·계정·DM 연동 없이 P0 화면과 화면 사이 이동을 목 데이터로 확인하는 것이다.

구현은 Codex가 `workspace-write` + `windows.sandbox="unelevated"` 샌드박스에서 한다. 이 샌드박스는 자식 프로세스 생성을 막을 수 있고(spawn EPERM) 패키지 설치용 네트워크를 보장하지 않는다(docs/development/claude-codex-workflow.md).

## 결정

1. **의존성 없는 바닐라 HTML·CSS·JavaScript(ES 모듈)** 로 만든다. 빌드 도구·프레임워크·npm 패키지를 쓰지 않는다.
   - 이유: 설치·빌드 없이 샌드박스에서 바로 검증할 수 있다. Vite 등은 esbuild 자식 프로세스와 패키지 설치가 필요해 Codex 샌드박스에서 검증이 막힐 수 있다.
   - 화면은 `(state) => HTML 문자열` 순수 함수로 만들어 Node 테스트에서 DOM 없이 렌더링을 검사한다.
2. 코드는 `web/` 아래에 둔다. 해시 라우터(`#/...`)로 이동하고, 목 데이터와 시나리오 프리셋으로 화면 상태를 바꾼다.
3. 검사는 Node 내장 `node:test`로 한다(`--test-isolation=none`). Node는 Codex 런타임의 v24를 기준으로 한다. 미리보기는 의존성 없는 `web/scripts/serve.mjs` 정적 서버로 한다(ES 모듈은 `file://`로 열리지 않음).
4. 외부 리소스(웹 폰트·지도 SDK·CDN)를 불러오지 않는다. 지도는 정적인 가짜 지도 위에 핀을 그린다. 지도 제공자는 미정이다.

이 결정은 정적 목업 단계에만 적용한다. 실제 서비스의 프런트엔드·백엔드 스택은 계정·DM 수신 방식을 정할 때 따로 결정하고, 그때 이 코드를 재사용할지 판단한다.

## 화면 분할

P0 58개 화면을 흐름별 브리프 4개로 나눈다. P1 보강안·후속 버전 보드는 범위에서 뺀다.

| 브리프 | 범위 | 화면 수 |
| --- | --- | --- |
| UI-01 | 스택·공통 셸 + 4.1 시작·연결(1-1~1-9) + 4.4 개인·공유 지도와 목록(4-1~4-8) | 17 |
| UI-02 | 4.2 초기 복제·다른 맵에 복제(2-1~2-7) + 4.6 장소 상세(6-1~6-6) | 13 |
| UI-03 | 4.3 링크 등록(3-1~3-7) + 4.5 처리함(5-1~5-8) | 15 |
| UI-04 | 4.7 이번 약속(7-1~7-6) + 4.8 맵·설정(8-1~8-7) | 13 |

각 브리프는 이전 브리프의 공통 셸·토큰·목 데이터를 재사용한다. 아직 구현하지 않은 화면으로 가는 버튼은 담당 브리프 ID를 적은 '준비 중' 화면으로 보낸다.
