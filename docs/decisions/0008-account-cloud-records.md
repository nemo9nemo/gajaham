# 0008 로그인 계정의 개인 기록을 서버에 보관하고 여러 기기에서 조회

- 날짜: 2026-11-03 / RES-01 조사 후 사용자 선택
- 상태: 사용자 요구 확정·정책/설계 반영. 실제 웹앱·서버 저장/동기화·운영 설정은 미구현
- 근거: “로그인하면 어디서든 내 기록 볼 수 있도록 해야 돼.”
- 대체: 결정0005/0006/0007의 로그인 계정 개인 원본 로컬 전용·서버 저장/동기화 금지·브라우저/기기 변경 후 복구 불가 정책
- 유지: 모바일 웹 우선·이메일/비밀번호 기본·게스트 개인 이용·2차 소셜·개인 맵 비공개·선택 공유·맵별 사본 독립·최소 운영 비용

## 확정한 요구

1. 가자함은 기본적으로 URL로 접속하는 웹앱이다. 설치는 이용 조건이 아니며 PWA 홈 화면 추가는 선택 사항이다.
2. 로그인 계정으로 저장한 개인 기록은 서버가 원본을 보관한다. 네트워크가 가능한 지원 기기/브라우저에서 같은 유효 계정으로 로그인하면 기존 기록을 조회한다. 사이트 데이터를 지워도 서버에 남은 계정 기록은 다시 조회할 수 있다.
3. 로그인 없는 개인 이용은 유지한다. 게스트 원본은 현재 브라우저의 IndexedDB에만 보관하고 로그인 전까지 다른 기기로 이어지지 않는다. 게스트 기록을 계정에 저장하는 동작은 대상/전송 항목을 안내하고 사용자가 선택한다.
4. 개인 기록의 클라우드 보관은 상대방 공개와 다르다. 개인 맵은 본인만 보고 공유 맵에는 선택한 별도 사본만 넣는다. 같은 계정 기기 간 변경 반영과 서로 다른 맵의 사본 독립을 구분한다.
5. 사이트 데이터 삭제/로그아웃은 서버 원본 삭제가 아니다. 기록 삭제·휴지통·계정 탈퇴는 서버 원본/참여권/캐시까지 포함해 별도 설계한다. 영구 삭제/탈퇴 처리된 데이터를 재로그인으로 되살리는 약속은 아니다.

## 기술 방향과 범위

최소 운영 부담과 기존 인증 자산을 고려해 **Firebase Authentication Web SDK + Cloud Firestore Standard + Firebase Hosting**을 우선 구현 방향으로 선정한다. 게스트만 IndexedDB 원본을 사용한다. 로그인 계정 캐시는 초기에는 메모리 중심이며 영속 캐시/오프라인 큐는 별도 구현/검증 전 자동 활성화하지 않는다. SDK 기본 동작에 앱 정책을 맡기지 않는다. [공식 서버 권한](https://firebase.google.com/docs/firestore/security/rules-conditions), [오프라인 동작](https://firebase.google.com/docs/firestore/manage-data/enable-offline)

실제 앱 경로·프레임워크·정확한 버전·Emulator/검사 명령·운영 리전·탈퇴 작업 실행 환경은 후속 WEB-01 브리프에서 고정한다. `web/`는 패키지를 추가하지 않는 목업이다. Android/Room와 `account/`의 기존 인증 계정 삭제 페이지는 이전 정책의 구현 이력이며 자동 업로드·이식·클라우드 원본 삭제를 이미 제공하는 것으로 읽지 않는다.

## 저장·인가·수명

- 서버 커밋 확인 후 계정 저장 완료를 표시한다. 전송 중/실패/권한 거절·응답 불명확을 완료로 표시하지 않는다. 초기 계정 쓰기는 온라인 확인을 기준으로 하며 미전송 입력이 다른 기기에도 있다고 약속하지 않는다.
- 서버/API/Rules의 검증된 UID로 개인 원본을 격리한다. 이메일/클라이언트 UID 문자열만으로 소유권을 인정하지 않는다. 소유자 변조·다른 사용자 조회·게스트 공유 참여를 차단한다.
- 재시도/게스트 업로드는 계정에 묶인 요청 식별자로 중복 생성을 방지한다. 서버 성공 전에 게스트 원본을 지우지 않고 부분 성공·실패·중복을 구분한다.
- 여러 기기의 동시 편집은 버전/충돌 검사로 오래된 폼의 무음 덮어쓰기를 막는다. 공유 사본은 원본과 편집 수명을 분리한다. [트랜잭션](https://firebase.google.com/docs/firestore/manage-data/transactions)
- 로그아웃/계정 변경 때 구독·작업·캐시를 UID/세대에서 분리한다. 다른 계정/게스트에 이전 원본을 노출하지 않는다. 다른 오프라인 기기의 캐시를 즉시 원격 삭제했다고 약속하지 않는다.
- 운영 백업/보존은 별도 데이터 흐름·비용·삭제 정책을 확정한다. 사용자용 JSON 백업/가져오기 UI는 이번 요구로 복원하지 않는다.

## 운영 비용과 완료의 의미

Firestore 무료 한도는 계정별이 아닌 프로젝트 DB의 개인+공유 합계로 계산한다. 기본 CRUD가 무료 한도에 들어가도 탈퇴 정리·백업·이미지·DM/분석까지 전부 무료라고 확정하지 않는다. 유료 활성화·도메인 구매·운영 프로젝트 생성/메일 발송·공개 배포는 이번 정책 변경에서 실행하지 않는다. [비용 조사](../research/server-personal-data-2026-11-03.md)

세부 기준은 [웹 계정 기록](../contracts/web-account-data.md), [게스트 로컬/캐시](../contracts/web-local-data.md), [인증·공유](../contracts/auth-and-guest.md), [AUTH-03 검사](../validation/AUTH-03-account-cloud-policy.md)다. 정책 반영과 실제 두 브라우저/운영 서버 검증 완료를 구분한다.
