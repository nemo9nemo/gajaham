# 0005 이메일 로그인·선택적 비로그인·개인 기록의 기기 내 보관

- 날짜: 2026-10-26
- 상태: 사용자 요구 확정·기능 분석, 실제 인증/정책 반영은 미구현
- 대체 범위: 결정 0003의 ‘1차 로그인 제외/2차 실제 로그인’ 순서와 계정 개인 기록의 클라우드 복구 제안
- 근거: 사용자의 로그인 기능 분석 요청 및 후속 선택 답변

## 확정한 요구

1. 기본 로그인은 이메일·비밀번호로 제공한다.
2. 카카오·구글 등의 간편 로그인은 2차 개발이다.
3. 로그인 없이도 개인 기능을 사용할 수 있다. 비로그인 상태에서 상대 계정 연결·공유 맵 참여는 허용하지 않는다.
4. 로그인 여부와 관계없이 **개인 기록은 앱 삭제 시 복구 불가**다. 로그인 계정의 존재를 개인 기록 백업으로 취급하지 않는다.
5. Galaxy 우선·광고 수익화와 개인 맵 비공개·선택 복제·맵별 독립 편집·저장 직전 인가 규칙은 유지한다.

## 요구를 충족하기 위한 설계 정책

- 개인 장소·메모·방문·처리함·휴지통 원본은 기기에만 보관한다. 개인 기록의 서버 저장·동기화·클라우드 백업·재설치 복구 경로를 만들지 않는다.
- 현재 개발 버전의 JSON 백업·가져오기는 최신 요구와 충돌하므로 출시 기능에서 제외해야 한다. 이번 분석으로 실제 버튼/코드를 제거한 것은 아니다. 업데이트 때 기존 기록을 삭제하지 않으며, 이미 사용자가 내보낸 외부 파일을 회수했다고 표시하지 않는다.
- 서버는 인증 정보와 계정/연결/명시적으로 공유한 데이터에 필요한 범위로 설계한다. 로그인 사용자에게도 개인 기록 서버 컬렉션을 만들지 않는다.
- ‘상대 계정 연결’과 ‘로그인 수단 연결’을 구분한다. 전자는 공유 맵의 두 사용자 연결, 후자는 2차 소셜 제공자를 같은 사용자 식별자에 연결하는 기능이다. Instagram DM 연결은 별도다.
- 공유 맵의 서버 사본·연결 관계 보존은 개인 원본 복구와 구분하는 설계 제안이다. 공유 종료·탈퇴·잔여 참여자 정책을 구현 전에 구체화한다. 이번 답변을 공유 데이터 보존 기간의 확정으로 확대하지 않는다.

## 구현 상태와 후속

현재 앱은 Room v2 개인 저장 기반이다. 실제 로그인·서버 인가·상대 연결·계정별 로컬 분리와 새 삭제/백업 정책은 미구현이다. [AUTH-01 기능 분석](../plans/AUTH-01-login-guest-analysis.md), [정책·설계 계약](../contracts/auth-and-guest.md), [검증 시나리오](../validation/AUTH-01-login-guest.md)를 다음 구현의 기준으로 삼는다. 이전 문서의 실행 증거는 당시 이력으로 보존한다.
