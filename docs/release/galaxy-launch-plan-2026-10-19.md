# 가자함 갤럭시 우선 출시·광고 수익·마케팅 기획

작성·공식 자료 확인: 2026-10-19. 검토 기준 코드: `82434a16fd79f48b51de9e940b1ecd13dff68e7f`.

이 문서는 **출시 준비 검토와 실행 제안**이다. Android 앱·실제 로그인·광고·백엔드를 구현하거나 스토어에 제출한 결과가 아니다. 기존 정적 목업의 완성과 서비스 출시 가능 여부를 구분한다.

## 1. 판단과 현재 기준

권장 순서는 **로그인 없이 개인 장소를 안정적으로 모으는 Android 앱 → 실제 로그인·복구·두 사람의 공유 맵 → 검증된 DM 자동 수신**이다. Galaxy는 기기 우선순위로 삼고 첫 배포 채널은 Google Play로 제안한다. Galaxy Store 동시 운영은 초기 출시의 선행 조건으로 두지 않는다.

사용자가 확정한 방향은 ① 1차 로그인 제외 ② 2차 실제 로그인까지 ③ 갤럭시 우선 ④ 광고 수익 창출이다. 이 문서의 네이티브 스택, 기능별 단계 배치, 예산, 기간, 지표는 이를 구체화한 **제안**이며 성과 예측이나 구현 완료 약속이 아니다. 계정 개설·결제·공개 배포·광고 집행·외부 연락은 수행하지 않았다.

현재는 58개 P0 화면과 목 데이터 상태 전이가 있는 정적 웹 목업이다. 아래 항목은 출시 전에 별도로 개발·검증해야 한다.

| 영역 | 현재 확인한 상태 | 출시 준비에서 보완할 일 | 우선순위 |
|---|---|---|---|
| 앱 배포 | HTML·CSS·ES 모듈, Android 프로젝트 없음 | 앱 ID·서명·AAB·설치·업데이트 경로 | 1차 필수 |
| 저장 | `web/src/store.js`의 메모리 상태 | 영속 DB, 프로세스 종료·재실행·마이그레이션 | 1차 필수 |
| 지도·검색 | 가짜 지도와 목 장소 | 실제 SDK, 검색 품질, 지점 확인, 이용 조건·쿼터 | 1차 필수 |
| 입력 | 목 링크와 분석 시나리오 | Galaxy 공유 메뉴의 실제 URL·텍스트 수신, 붙여넣기 | 1차 필수 |

| 복구·삭제 | 설정 화면의 미정 정책·미리보기 | 실제 파일 백업·복원, 휴지통·전체 삭제 | 1차 필수 |

## 2. 단계별 제품 범위

| 구분 | 1차: 로그인 없는 개인 앱 | 2차: 실제 로그인과 안전한 공유 |
|---|---|---|
| 이용 시작 | 가입·서비스 계정 생성 없이 시작 | 로그인은 백업·공유가 필요할 때 요청, 개인 이용 유지 |
| 저장 위치 | 앱 전용 로컬 DB | 본인 계정의 개인 맵, 선택한 장소만 2인 공유 맵 |
| 받는 경로 | Android 공유 메뉴, URL 붙여넣기, 직접 장소 검색 | 기존 경로 유지, 계정 간 동기화 |
| 핵심 가치 | 출처·장소·저장 이유를 묶고 다시 찾아 길찾기 | 기기 교체 복구, 둘이 후보를 고르고 함께 사용 |
| 데이터 복구 | 사용자가 내보낸 파일로 복원 | 동의한 로컬 자료의 계정 이전과 서버 백업 |
| 광고 | 저장 목록의 제한된 네이티브 광고 | 동일 원칙, 보상형은 원가 검증 후 별도 실험 |
| 이번 단계에서 약속할 기능 | 실제 동작한 범위만 스토어에 표시 | 로그인뿐 아니라 인가·탈퇴·권한 종료까지 검증 |

1차를 **로그인 없는 공개 가능 제품**으로 가정해 설계했다. 1차가 내부 테스트만을 뜻한다면 같은 핵심 기능과 데이터 안정성을 검증한 뒤 공개 시점만 2차로 옮긴다. 월 운영·마케팅 예산과 개발자 계정 유형은 아직 확인되지 않았다. 기본안은 1인 운영·한국 이용자·소액 검증이며 자동 결제나 집행을 승인한 것으로 해석하지 않는다.

기존 10월 10~12일 문서의 'DM·모바일 웹 우선, 첫 베타에 로그인·공유 포함'과 출시 순서가 달라진다. **로그인 단계와 갤럭시 우선 요구가 최신 기준**이다. DM 수신과 공유 맵 자체를 폐기하는 것이 아니라, 위 단계 배치는 안전한 실행을 위한 제안으로 구분한다. 개인 맵의 비공개, 선택적 복제, 맵별 독립 편집, 저장 직전 권한 검사는 계속 지킨다.

## 3. 1차에서 반드시 완성할 경험

권장 흐름은 `인스타 공유 → 가자함 → 링크 먼저 안전하게 접수 → 장소 확인 → 저장 이유 한 줄 → 개인 맵 → 나중에 다시 열기·길찾기`다.

1. **공유 접수부터 보존한다.** 화면에서 '접수됨'을 보여주기 전에 URL·접수 ID를 로컬 트랜잭션으로 저장한다. 앱 종료·네트워크 끊김·동일 Intent 재전달에도 접수가 사라지거나 무한 중복되지 않아야 한다. 장소 미확정 항목은 처리함에 남기고 확정된 지도 핀과 구분한다.
2. **틀린 장소를 확정하지 않는다.** 동명 지점·여러 장소·영상에만 정보가 있는 링크는 사용자가 고르게 한다. 원본 URL과 확인 상태를 남기고, 근거 없는 메뉴·주소는 만들지 않는다. 같은 URL의 재접수와 같은 장소의 다른 참고 글을 구분한다.
3. **다시 찾는 이유를 남긴다.** 저장 이유·먹고 싶은 메뉴는 선택 입력, 방문 여부·지역·카테고리로 찾게 한다. 원본 열기와 외부 지도 길찾기는 실제 앱 연결·웹 대체 경로까지 구현한다. 기본 개인 저장에 위치 권한을 요구하지 않는다.
4. **기기 안의 기록을 복구할 수 있게 한다.** 버전이 있는 JSON 백업을 Android 파일 선택기로 내보내고 가져온다. 복원 전 건수·중복·오류를 보여주며 실패하면 원본 DB를 유지한다. 백업 파일에 포함되는 메모·URL을 안내한다. 앱 삭제·저장 공간 초기화 시의 손실 위험도 온보딩과 설정에 설명한다.
5. **삭제 정책을 실제로 동작시킨다.** 로컬 휴지통은 30일 후 영구 삭제하는 안을 제안한다. 즉시 영구 삭제·전체 초기화도 제공하며, 사용자가 이미 내보낸 파일은 앱이 회수하지 못함을 알린다. 선택적 SDK·서버 로그의 보존은 로컬 장소 삭제와 별도로 명시한다.

Android 공유 기능은 전달받은 MIME·URL·텍스트를 처리하는 인터페이스다. 공유 버튼을 눌렀다는 사실만으로 인스타 본문·사진·영상 전체를 얻는다고 가정하지 않는다. 실제 입력을 기기·앱 버전별로 검사한다. [Android 공유 수신](https://developer.android.com/develop/ui/compose/sharing/receive)

자동 분석은 출시 매력을 좌우하므로 초기에 기술 검증한다. 허용된 접근으로 확보한 자료만 사용하고 `접수 성공 / 자료 확보 / 장소 후보 정확도 / 사용자 확정`을 따로 측정한다. 로그인·쿠키 수집이나 비공식 우회 수집을 전제하지 않는다. 자동 분석을 못 만들면 수동 확인 제품으로 정직하게 소규모 검증하고, 자동 저장을 내세운 대규모 광고는 집행하지 않는다.

## 4. Galaxy·Android 구현 제안

**Kotlin + Jetpack Compose + Room + WorkManager**로 별도 Android 앱을 만드는 안을 권장한다. 공유 Intent, 로컬 보존, Galaxy의 프로세스 종료, 광고·지도 SDK 연결이 핵심이기 때문이다. 기존 `web/`은 화면·정책·상태 전이의 참고 자산으로 유지한다. 정적 목업에 패키지를 추가해 서비스처럼 보이게 만들지 않는다. Android 의존성은 향후 별도 구현 브리프에서 안정 버전과 검증 명령을 정한다. [Room](https://developer.android.com/training/data-storage/room), [영속 백그라운드 작업](https://developer.android.com/develop/background-work/background-tasks/persistent)

- 지원 하한은 Android 10/API 29를 **초기 제안**으로 두고 실제 타깃 기기 조사로 조정한다. 현재 Google Play의 일반 휴대폰 신규 앱·업데이트 제출 기준은 Android 16/API 36 이상이다. `targetSdk`와 설치 가능한 최소 OS는 다르다. 업로드 직전 정책을 다시 확인한다. [Play target API](https://developer.android.com/google/play/requirements/target-sdk)
- Galaxy A 계열 1대, S 계열 1대, 최신 OS 기기와 지원 하한 환경을 최소 조합으로 잡는다. 폴더블·큰 글꼴·다크 모드·TalkBack·제스처 내비게이션·회전·멀티 윈도도 확인한다. 실물 기기가 없는 항목은 에뮬레이터 검사와 미검증 위험을 구분한다.
- One UI 절전·프로세스 종료·공유 중 뒤로 가기·빠른 연속 공유·앱 업데이트 후 DB 유지·지도 SDK 초기화 실패·광고 요청 실패를 실제 기기에서 검사한다. SDK의 ABI·네이티브 라이브러리와 현행 Play 호환성 요구도 AAB 검사에 포함한다.
- 초기에는 백그라운드 위치·연락처·알림 읽기·접근성으로 다른 앱을 읽는 권한을 쓰지 않는다. 현재 위치 정렬을 나중에 넣어도 사용자가 눌렀을 때의 권한과 거부 대체 경로부터 설계한다.
- Android는 기본 자동 백업에 앱 데이터를 포함할 수 있다. 클라우드 백업과 기기 간 이전을 명시적으로 설계하고, Android 12 이상 `dataExtractionRules`와 이전 OS의 백업 규칙을 함께 적용한다. `allowBackup=false` 하나로 모든 제조사의 기기 이전이 차단된다고 보장하지 않는다. Galaxy 기기 이전도 확인한 뒤 개인정보 문구를 쓴다. [Android 백업 동작](https://developer.android.com/identity/data/autobackup)

지도는 **카카오맵 SDK·장소 검색을 먼저 실증**하되 최종 제공자는 검색 품질·저장 허용 범위·비용을 확인한 뒤 결정한다. API 접근 권한이 결과의 무기한 저장·재배포·타일 캐시 권한을 자동으로 뜻하지 않는다. 로고·출처 표시는 SDK 정책에 맞추고 광고가 가리지 않도록 한다.

카카오는 2026-07-21부터 무료 쿼터 제공 방식을 바꿨다. 개발자 계정에서 첫 번째로 활성화한 앱에만 무료 쿼터가 제공되고, 두 번째 앱이나 초과 사용은 유료 설정이 필요하다. 개발·운영 앱을 나눌 때도 확인해야 한다. 검색 요청 수·429·과금 대상량을 관측하고 유료 호출 상한·실패 대체 경로를 둔다. [현재 이용 조건](https://developers.kakao.com/docs/ko/kakaomap/common), [쿼터·추가 요금](https://developers.kakao.com/docs/ko/getting-started/quota)

## 5. 2차: 인증보다 데이터 경계가 더 중요하다

실제 로그인은 **Google Credential Manager + Firebase Authentication을 우선 실증**하는 안을 제안한다. 국내 이용자의 로그인 이탈이 확인될 때 Kakao 로그인을 추가한다. 비밀번호·문자 인증을 직접 운영하는 범위는 초기에 늘리지 않는다. Firebase를 쓰더라도 가입만 성공했다고 공유 맵이 안전해지는 것은 아니다. 서버 인가와 삭제·복구를 함께 구현한다. [공식 Google 로그인 연동](https://firebase.google.com/docs/auth/android/google-signin)

백엔드는 Firebase Auth·Firestore·서버 함수 조합을 우선 비교안으로 삼되 리전, 국외 처리, 비용 한도, 삭제·백업 요건을 확인한 후 별도 결정한다. 실증 전 특정 무료 구간이나 무과금을 보장하지 않는다. 초대 코드·멤버십 변경·민감한 복제 작업은 서버가 검증하고 클라이언트 값만 신뢰하지 않는다.

| 반드시 해결할 상황 | 설계·검증 기준 |
|---|---|
| 비회원 기록을 계정으로 옮김 | 사용자 선택·건수 미리보기, 배치 ID로 중복 방지, 서버 확인 전 로컬 원본 유지 |
| 로그인 취소·오프라인·재시도 | 부분 성공을 구분하고 이어서 처리, 새 계정으로 임의 이전 금지 |
| 로그아웃·다른 계정 로그인 | 개인 DB·캐시·대기 작업의 소유자 분리, 이전 계정 자료 노출 방지 |
| 개인 맵 조회·저장 | 모든 요청에서 본인 여부 검사, 다른 참여자의 개인 맵은 조회·복제 대상에서 배제 |
| 연결 코드 | 예: 10분 만료·단일 사용·재발급 시 이전 무효·시도 제한, 동시 사용을 원자적으로 처리 |
| 공유 맵 복제·편집 | 저장 직전 활성 참여권 재검사, 종료된 권한의 대기 작업 차단, 맵별 독립 편집 |
| 연결 종료 | 접근 즉시 차단, 기본 저장 위치 조정, 내 기록 보존·복제 범위를 명확히 안내 |
| 계정 삭제 | 앱 안과 외부 웹의 요청 경로, 인증 제공자·개인 DB·연결 정보·백업 보존까지 삭제 계약 작성 |

공유 기록은 한 사람의 탈퇴와 다른 참여자의 이용 권리가 충돌할 수 있다. 공유에 넣은 장소·개인 메모·작성자 식별자를 나눠 잔여 참여자가 볼 수 있는 범위를 고지하고, 보존 근거가 없는 개인정보는 제거한다. 마지막 참여자 종료·백업 만료·법정 보관 예외까지 정책과 실제 삭제 작업으로 일치시킨 후 공개한다. 보존 기간을 아직 구현되지 않은 보장으로 표시하지 않는다.

Play는 앱에서 계정을 만들 수 있으면 앱 내부와 외부 웹의 삭제 요청 경로를 요구한다. 단순 로그아웃·비활성화로 대신하지 않는다. [계정 삭제 요건](https://support.google.com/googleplay/android-developer/answer/13327111?hl=en)

**앱 로그인과 Instagram DM 연결은 별개**다. 이번 검토에서는 Meta 개발자 문서 원문 요청이 429로 제한되어 최신 권한·심사 조건을 충분히 재확인하지 못했다. 기존 기획의 근거와 [Meta 공식 API 자료](https://www.postman.com/meta/instagram/documentation/6yqw8pt/instagram-api)를 출발점으로 삼되, 서비스 계정·웹훅·수신 데이터·서명 검증·재전송·삭제·허용 회신 범위를 실제로 입증한 뒤 일정에 넣는다. 기존 개인 DM 전체 읽기나 URL만으로 모든 영상 분석을 출시 약속으로 내걸지 않는다.

## 6. 광고는 작게 시작하고 핵심 사용을 보호한다

첫 수익원은 **AdMob 네이티브 광고 한 종류**를 권장한다. 저장 목록의 일반 카드 5개 뒤에서 시작하되 이는 제품 배치 제안이다. 실제 기기에서 광고 표시·AdChoices·오클릭 위험을 확인하고 부족한 목록에는 억지로 광고를 넣지 않는다. 지도 핀·저장한 장소·유료 추천으로 오인하지 않게 '광고'를 표시한다. SDK의 클릭 처리를 쓰고 버튼 위에 광고를 겹치지 않는다. [네이티브 광고 구현](https://developers.google.com/admob/android/native/advanced)

| 지면·행위 | 제안 |
|---|---|
| 첫 실행·첫 저장·공유 접수 중 | 광고로 막지 않음 |
| 지도 조작·원본 열기·길찾기·파일 복구 | 광고 시청 조건을 붙이지 않음 |
| 충분한 저장 목록 탐색 | 라벨이 있는 네이티브 광고, 밀도와 실제 노출 측정 |
| 전면·앱 오픈 광고 | 초기에는 도입하지 않음; 특히 저장 도중 예고 없이 표시하지 않음 |
| 광고 실패·동의 상태 확인 실패·오프라인 | 로컬 저장·열람·직접 입력·확정 대기 유지, 허용 확인 전 광고 요청 금지 |
| 보상형 | 후속 단계에서 선택적 추가 분석 이용권을 검증; 기본 저장 기능 유지 |

예상하지 못한 전면 광고나 잦은 방해 광고는 정책·이탈 위험이 있다. 보상형은 사용자가 보상과 조건을 알고 선택하게 하고, 거절해도 정상 이용이 가능해야 한다. 광고 클릭에 보상하거나 개발자 수익을 이유로 클릭을 부탁하지 않는다. [전면 광고 정책](https://support.google.com/admob/answer/6201362?hl=en), [보상형 정책](https://support.google.com/admob/answer/7313578?hl=en)

개발·테스터는 테스트 광고·테스트 기기로 검증한다. 본인 실광고 클릭이나 리뷰·설치 보상과의 결합을 하지 않는다. 광고 SDK 설치만으로 정상 광고 수익이 시작되는 것도 아니다. 지원 스토어 등록·AdMob 앱 준비 검토와 `app-ads.txt` 확인을 준비한다. 개발자 웹사이트의 루트 경로에 실제 게시자 정보로 파일을 제공하고 스토어 개발자 사이트와 연결한다. [테스트 광고](https://developers.google.com/admob/android/test-ads), [앱 준비 절차](https://support.google.com/admob/answer/15948559?hl=en), [app-ads.txt](https://support.google.com/admob/answer/9363762?hl=en)

로그인이 없어도 광고 SDK가 기기 식별자·네트워크 정보를 처리할 수 있다. 비개인화 광고도 개인정보 처리가 전혀 없다는 뜻이 아니다. 장소·메모·원본 URL·정밀 좌표를 광고 타기팅에 보내지 않고, 광고 ID를 계정·저장 자료와 연결하지 않는다. UMP의 적용 지역별 절차·광고 요청 가능 상태·개인정보 옵션을 구현하고 한국의 의무는 실제 데이터 흐름에 맞춰 별도 검토한다. [UMP](https://developers.google.com/admob/android/privacy), [데이터 보안 신고](https://support.google.com/googleplay/android-developer/answer/10787469?hl=en)

## 7. 수익성 계산: 실제 매출 추정과 구분

아래 eCPM은 **한국 시장 평균이나 확정 단가가 아닌 민감도 분석용 가정**이다. 실제 광고가 렌더링된 노출을 하루 활성 이용자당 2회로 가정했다. 미동의·광고 미충전·차단·미열람 등으로 노출이 줄어들면 매출도 줄어든다. DAU는 하루 실제 활성 이용자이며 누적 설치 수와 다르다.

`월 광고 매출 = DAU × 2회 × 30일 × 실현 eCPM ÷ 1,000`

| DAU | 월 실제 노출 가정 | eCPM 500원 | eCPM 1,500원 | eCPM 3,000원 |
|---:|---:|---:|---:|---:|
| 100 | 6,000 | 3,000원 | 9,000원 | 18,000원 |
| 1,000 | 60,000 | 30,000원 | 90,000원 | 180,000원 |
| 10,000 | 600,000 | 300,000원 | 900,000원 | 1,800,000원 |

기준 가정에서는 **DAU 1명당 월 매출 90원**, 월 매출 100만 원에 약 **DAU 11,112명**이 필요하다. 모두 서버·지도·분석·운영 인건비·세금 등을 빼기 전이다. 실제로 주말에만 많이 열리는 서비스라면 월별 일평균 DAU로 계산해야 한다.

고정비 월 5만 원, 변동비 0원을 놓은 단순 비교에서는 약 DAU 556명부터 고정비만 덮는다. 이는 제공사 견적이나 실제 손익분기점이 아니다. 실제 식은 `고정비 ÷ (활성이용자당 월 광고 매출 - 월 변동비)`이며, 분모가 0 이하이면 이용자가 늘수록 개선되지 않는다. AI·지도 API 비용과 저장 수 증가를 반드시 넣는다.

카카오의 현재 추가 쿼터 표에는 키워드 검색 건당 2원, Android/iOS 지도 건당 0.1원이 제시되어 있다. **유료 적용 대상 호출**에 관한 수치이며 무료 쿼터·앱 활성화 순서·호출 단위를 함께 확인해야 한다. 단순 예로 유료 검색 1만 건은 2만 원이다. 검색을 입력 글자마다 무제한 호출하지 말고 중복·취소·오류 재시도와 제공자 약관상 허용된 캐시를 설계한다. [공식 요금·쿼터](https://developers.kakao.com/docs/ko/getting-started/quota)

보상형도 원가를 없애주지 않는다. 예를 들어 eCPM 1만 원을 **가정**하면 광고 1회 매출은 10원이다. 분석 1회에 20원이 든다는 별도 **가정**에서는 적자다. 실제 단가와 실패·재시도 비용을 측정하기 전에 '광고 한 번으로 무제한 AI 분석'을 약속하지 않는다.

유료 이용자 유치는 더 엄격히 본다. 한 이용자가 생애 20일 활동하고 하루 2회 광고를 보면 기준 가정의 광고 매출은 60원이다. 활성 이용자 1명을 얻는 비용이 1,000원이라는 가정이면 광고만으로 회수되지 않는다. 설치당 비용과 활성 이용자당 획득비를 혼용하지 않고, **측정한 이용자 생애 매출에서 변동비를 뺀 금액이 획득비를 넘을 때만** 집행을 확대한다.

따라서 초기 수익 전략은 '광고를 많이 보여주기'보다 **저장 원가 제한 → 매주 다시 열 이유 확보 → 자연 유입 → 실제 노출·eCPM·원가 측정**이다. 매장 협찬은 후속 선택지로 두고 도입할 경우 광고 라벨과 개인 저장 데이터의 독립성을 유지한다. 초기 계획의 필수 매출로 계산하지 않는다.

## 8. 경쟁과 고객: 가입 없음만으로 차별화되지 않는다

10월 19일 공식 스토어 설명을 다시 확인했다. 아래는 공개 설명의 요약이며 직접 설치한 품질·정확도·수익 검증 결과가 아니다.

제품 문구는 **“저장한 이유까지 기억하는 나의 지도”**를 제안한다. 1차는 개인의 정리·재발견, 2차는 “각자의 장소는 지키고, 함께 갈 곳만 모으기”를 더한다. 가입 없음·AI·공유지도 자체를 독점적인 기능이라고 주장하지 않는다.

5~10명의 목표 고객에게 경쟁 앱과 같은 링크를 저장하고, 며칠 뒤 특정 장소를 다시 찾는 과제를 부탁하는 계획을 세운다. 저장 완료 시간·수정 횟수·지점 오류·나중에 찾는 시간을 비교한다. 직접 시험하기 전 경쟁 앱이 느리거나 부정확하다고 홍보하지 않는다. 수동 흐름의 부담이 크면 자동 분석의 범위를 좁혀 먼저 개선한다.

## 9. 출시와 마케팅 실행안

### 첫 배포 전

- 15~20명의 실제 Galaxy 테스터 후보를 확보하는 모집안을 준비한다. 신규 개인 Play 계정 조건이 적용되면 최소 12명이 연속 14일 참여한 비공개 테스트가 필요하며 이후 프로덕션 접근을 신청한다. 모든 계정에 일괄 적용되거나 14일 뒤 자동 승인되는 규칙은 아니다. [Play 테스트 요건](https://support.google.com/googleplay/android-developer/answer/14151465?hl=en)
- 공식 스토어 제목 초안: **가자함 - 인스타 장소·맛집 저장**. 소개 초안: **갤럭시 공유 메뉴로 링크를 모으고, 장소와 저장 이유를 나의 지도에서 다시 찾아요. 회원가입 없이 시작하세요.** 실제 구현과 다른 표현은 제출하지 않는다. 자동 확정이 아니라면 '장소를 확인해 저장'을 설명한다.
- 스크린샷 5장의 메시지: 공유로 접수 / 장소·지점 확인 / 저장 이유 / 내 지도에서 찾기 / 파일 백업. 2인 공유·DM·AI가 미구현이면 출시 스크린샷에서 작동하는 기능처럼 보여주지 않는다.
- 개발자 도메인에 소개·문의·개인정보처리방침·광고 관련 안내를 준비하고, 2차에는 외부 계정 삭제 경로를 추가한다. `app-ads.txt`는 도메인 루트에서 제공한다.

### 콘텐츠와 유입

| 소재 | 15초 영상 구성 | 클릭 후 기대 행동 |
|---|---|---|
| 저장함에서 잊힌 맛집 | 찾지 못하는 상황 3초 → 공유·확인 7초 → 주말 지도에서 다시 찾기 5초 | 첫 장소 1개 저장 |
| 갤럭시 공유 사용법 | 실제 Galaxy 공유 메뉴 → 가자함 선택 → 출처·메모가 남은 카드 | 사용법 이해 후 설치 |
| 왜 저장했더라 | '들기름 막국수 먹으러' 메모 → 카테고리·지역으로 재발견 | 다음 외출 때 다시 열기 |

릴스·쇼츠를 주 3개씩 올리는 안으로 시작하고, 자극적인 다운로드 숫자보다 저장·재방문 결과가 나오는 소재를 남긴다. 소유하거나 사용 허락을 받은 예시 콘텐츠와 화면을 사용하며 타인의 계정·얼굴·비공개 게시물을 노출하지 않는다. 실제 앱이 준비되기 전에는 목업임을 명시한다.

초기 채널은 본인 계정의 짧은 시연, 사용 허용된 커뮤니티의 테스터 모집, Galaxy 사용법 검색 콘텐츠다. 카페·커뮤니티 규칙을 지키고 무단 홍보·대량 DM·설치나 별점 보상은 하지 않는다. 작은 크리에이터 협업은 직접 사용한 시연과 광고 표시 조건을 문서화한 뒤 검토한다. 이 문서는 연락·게시·계약을 실행한 기록이 아니다.

2차에서만 함께 쓰기 초대가 성장 경로가 된다. `활성 개인 이용자 → 초대 시도 → 상대 로그인 → 연결 확인 → 두 사람 모두 재사용`을 측정한다. 친구의 개인 장소를 자동 공개하거나 주소록 업로드로 초대를 늘리지 않는다. 공유 가능한 안내·백업 파일이 개인 기록 공개 링크로 오해되지 않도록 구분한다.

### 예산과 확대 조건

| 월 가용 예산 가정 | 권장 운영 |
|---|---|
| 10만 원 이하 | 도메인·필수 운영을 우선, 기존 보유 기기로 테스트, 자연 유입·인터뷰, 유료 광고 보류 |
| 10만~50만 원 | 운영비와 예비비 확보, 콘텐츠 제작 실험. 유지율·원가가 확인된 뒤 작은 유료 소재 실험 검토 |
| 50만 원 이상 | 예산이 커도 바로 설치 광고를 확대하지 않음. 측정한 기여 이익과 획득비에 따라 단계 집행 |

위는 예산 배분 원칙이며 비용 견적이나 승인된 집행액이 아니다. 개발자 등록·테스트 기기·디자인 제작 등 일회성 비용과 월 운영비를 별도로 적는다. 개발자 계정·개인/사업자 상태·정산·세무·개인정보 의무는 실제 운영 주체에 맞춰 준비한다.

## 10. 성과 지표와 의사결정

핵심 지표는 **주간 저장 장소 재열람 또는 길찾기에 도달한 이용자 수**다. 광고 노출 수만 올리는 변경은 제품 개선으로 판단하지 않는다. 아래 숫자는 초기 내부 목표 제안이며 시장 평균이나 달성 예상치가 아니다.

| 지표 | 정의 | 초기 판단 기준 제안 |
|---|---|---|
| 첫 저장 활성화 | 신규 이용자 중 24시간 내 장소 1개 확정 저장 비율 | 60% 이상을 목표로 마찰 조사 |
| 공유 접수 보존 | 접수 완료 안내 뒤 재실행해도 항목이 남는지 | 검증 시나리오의 유실·오저장 0건 |
| 장소 확정 정확도 | 검증 표본에서 최종 확정 장소·지점이 맞는 비율 | 잘못된 자동 확정은 출시 차단, 미확정 처리 별도 집계 |
| D7 유지 | 첫 사용일 기준 7일째 핵심 행동을 한 비율 | 성숙 코호트 100명 이상에서 20%를 검토 기준으로 시작 |
| 재발견 | 활성화 이용자 중 2주 안에 저장 장소를 다시 열거나 길찾기한 비율 | 30%를 목표로 인터뷰와 함께 판단 |
| 광고 수익 | 실제 노출·실현 eCPM·활성 이용자당 매출 | 광고 미충전·동의 제외와 원가를 함께 기록 |
| 획득 효율 | 채널별 활성 이용자 획득비와 생애 기여 이익 | 관측 근거 없이 유료 집행 확대 금지 |

광고 없는 집단과 광고가 가능한 집단의 이탈을 비교하되 동의 상태 차이를 광고 효과로 오인하지 않는다. 표본이 작으면 인원·분모·기간을 그대로 보고 통계적 확정으로 표현하지 않는다. 저장 실패나 유실이 생기면 즉시 중단하고, D7이 5%p 이상 악화하는 신호가 반복되면 광고 밀도부터 줄이는 운영 기준을 제안한다. D30은 실제 30일이 지난 코호트로만 계산한다.

로그인 없는 앱의 전 이용자를 몰래 식별해서 유지율을 계산하지 않는다. SDK·설치 식별자·수집 목적·동의가 확정된 측정 대상 안에서 집계하고 선택 편향을 적는다. 서버에 보내는 이벤트 예시는 `capture_received`, `place_confirmed`, `saved_place_opened`, `directions_opened`, `backup_completed`, `ad_impression`이며 URL·장소명·메모·좌표·이메일은 속성에 넣지 않는다. 수집 도구를 아직 설치하거나 이벤트를 전송한 것은 아니다.

## 12. 실행 순서와 완료의 의미

1. **실증 단계:** Galaxy 공유 실제 데이터, 지도 검색·저장 약관·쿼터, 자동 분석 가능한 범위를 확인한다. 경쟁 사용 과제와 5~10명 인터뷰 계획도 함께 준비한다. 이 결과로 1차 공개 설명과 구현 브리프를 확정한다.
2. **1차 개발:** Android 앱·영속 저장·지도·처리함·수동 확정·백업·삭제를 먼저 완성하고 광고·동의·운영을 붙인다. 작은 실험 앱이 아니라 실제 설치·업데이트·손실 방지를 기준으로 검사한다.
3. **1차 비공개 테스트:** 실기기·저장 링크·복원·광고 테스트를 진행한다. 해당 개인 계정 요건은 14일 연속 참여 기간을 일정에 별도로 확보한다. 비공개 테스트 통과와 공개 심사 승인을 구분한다.
4. **1차 공개·학습:** 초기 200~500 설치는 모집 목표로만 두고 첫 저장·다음 주 재사용·실제 광고 원가를 본다. 심사 기간과 획득 성과를 확정 날짜로 약속하지 않는다. 문제가 없을 때 도달 범위를 넓힌다.
5. **2차 개발·검증:** 실제 로그인·비회원 이전·백업·2인 공유·탈퇴를 구현한다. 로그인 버튼만 연결한 상태로 완료 처리하지 않는다. 개인 저장에서 발견한 유실 문제는 2차까지 미루지 않는다.
6. **DM·추가 수익:** 공식 수신·자료 확보 실증 후 DM 일정을 정하고, 분석 원가를 감당할 때 선택적 보상형·협찬을 실험한다. iOS·Galaxy Store 확장은 유지율과 채널별 수요를 보고 판단한다.

기간은 인력·Android 도구·테스트 기기·심사 계정 상태가 미확정이므로 날짜를 확정하지 않는다. 실증·개발·비공개 테스트·심사·D7/D30 관측을 별개 기간으로 관리한다. 14일 테스트나 D30 관측을 개발 시간에 가려 압축하지 않는다.

이번 산출물의 완료 범위는 출시 보완점·단계별 제품안·기술 제안·광고 수익 시나리오·마케팅·출시 검사 기준의 문서화다. **APK/AAB 빌드, 실제 기기 테스트, API 계약·요금 확정, 인증·광고 연동, 법적 신고·심사·출시·집행은 미실행**이다. 검증 결과와 제안 목표를 혼동하지 않는다.
