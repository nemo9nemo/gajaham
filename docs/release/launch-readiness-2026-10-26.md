# 가자함 실제 출시까지 남은 작업

**2026-11-03 웹앱 전환:** 이 문서의 L01~L10은 Android 출시 점검 이력이다. 현재 출시 대상·잔여 개발·도메인 없는 운영 비용은 [WEB-00](../plans/WEB-00-webapp-transition.md), [결정 0007](../decisions/0007-webapp-first-low-cost.md)을 우선한다. Android AAB/서명·Play 심사·AdMob은 현 웹 출시 선행 조건에서 제외한다. 이메일/게스트·개인 로컬 전용·공유 선택 규칙은 유지하고 웹의 브라우저 저장·PWA·실제 지도·운영 검증은 새로 수행해야 한다. 아래 APK·기기·검사 기록은 웹 완료 증거가 아니다.

점검일: 2026-10-26 / 검토: Codex / 최초 점검 코드: `21da94a68de8c7d21bbe70292c966f38b04c2d64`. 전체 브랜치 재리뷰에서 발견한 저장 정확성 2건의 후속 조치는 [FIX-LAUNCH-01](../plans/FIX-LAUNCH-01-save-integrity.md)을 따른다.

**후속 요구/구현 반영 2026-10-27:** 기본 이메일·비밀번호 로그인 + 비로그인 개인 이용, 2차는 카카오·구글 간편 로그인이다. 모든 개인 원본은 기기 내 보관·앱 삭제 후 복구 불가다. [AUTH-02](../plans/AUTH-02-email-local-mode.md)에서 공식 이메일 SDK·Room v3 계정별 로컬 분리·파일 복구 경로 제거·외부 삭제 페이지를 구현했다. [최신 검사](../validation/AUTH-02-email-local-mode.md)를 보며 운영 인증 설정·메일·공개 호스팅·실기기 완료와 구분한다. 아래 10월 26일 검사 개수는 해당 시점 기록이다.

이 문서는 코드·기존 검사 증거·공식 배포 정책을 확인한 **출시 준비 점검**이다. 최초 점검의 ‘1차 로그인 제외·2차 실제 로그인’ 단계와 개인 기록 클라우드 복구 제안은 위 후속 요구로 대체한다. 갤럭시 우선·광고 수익화는 유지하며 세부 범위·순서·출시 기준은 실행 제안이다. 계정 등록·스토어 제출·광고 집행 완료 보고가 아니다.

## 현재 판정

**개인 저장 기반은 구현됐지만 공개 출시 준비는 완료되지 않았다.** 실제 지도·장소 검색, 광고 수익화, 개인정보·운영 준비, 갤럭시 실기기 검증, 출시 배포가 남았다. 현재 설치 파일은 개발용 debug APK와 서명 없는 release APK다. 스토어에서 내려받고 업데이트하는 출시본과 다르다.

정적 목업 58개 화면과 Android 개인 앱의 구현 범위는 다르다. 목업의 로그인·공유·DM·자동 분석 화면은 실제 기능의 완료 증거가 아니다. 완료율을 화면 수나 테스트 개수로 계산하지 않는다.

L01은 지도 앱으로서의 제품 요건이다. 현재 코드를 링크·메모 정리 도구로 먼저 시험하는 것은 가능하지만 지도·자동 분석을 제공한다고 소개할 수 없다. 실제 장소 검색이 붙으면 이름·주소를 모두 타이핑하는 부담을 먼저 줄이고, 자동 분석의 추가 가치와 원가를 별도로 검증한다.

지도 제공자는 카카오를 우선 실증하는 기존 제안을 유지한다. 앱/패키지·출시 서명에 맞는 키 제한, 결과 저장·출처·로고·캐시 이용 조건, 무료 적용 앱·쿼터·과금·중단 방식을 확인해야 한다. 2026-07-21부터 무료 쿼터 방식이 변경됐고 개발자 계정에서 첫 활성화 앱 여부를 확인해야 한다. 등록 상태와 결과의 장기 저장 허용 범위는 이번 점검으로 확인되지 않았다. 모바일용 공개 키의 제한과 서버 비밀 키의 보관을 구분한다. [카카오 공식 안내](https://developers.kakao.com/docs/ko/kakaomap/common)

광고는 목록 탐색 중 한 종류부터 도입하고 첫 저장·공유 도중 전면 광고를 넣지 않는 안을 유지한다. UMP 동의 정보 갱신·필요한 폼/개인정보 옵션·광고 요청 가능 상태를 검증한다. 한국 관련 의무도 실제 데이터 흐름에 맞춰 확인하며 UMP 하나로 전부 충족됐다고 판단하지 않는다. 지급 정보·지원 스토어·앱 검토·소유권 확인은 SDK 개발과 별도 절차다. 스토어 등재와 AdMob 검토의 의존성이 있으므로 출시 당일 정상 수익을 보장할 수 없다. [UMP 공식 구현](https://developers.google.com/admob/android/privacy), [AdMob 준비·검토·정산](https://support.google.com/admob/answer/15948559?hl=en)

로그인 없는 버전도 처리방침과 실제 SDK 흐름 확인이 필요하다. Play는 앱 내 처리방침 및 공개 URL, 정확한 데이터 보안 신고를 요구한다. 비공개 테스트에도 Data safety 신고가 적용되므로 공개 직전에만 준비할 일이 아니다. 현재 네트워크 권한이 없는 앱의 설명을 광고·지도 도입 후 그대로 사용하지 않는다. [Play 사용자 데이터 정책](https://support.google.com/googleplay/android-developer/answer/10144311?hl=en), [데이터 보안 신고 대상](https://support.google.com/googleplay/android-developer/answer/10787469?hl=en)

## 자동 분석·DM의 배치

- **자동 분석:** 현재 미구현이다. 실제 전달 자료와 허용된 접근 범위를 먼저 실증한다. 기존 기획의 실제 링크 30개 표본(본문 정보 10/영상·이미지 중심 10/다지점·행사 등 10)에서 접수·자료 확보·후보 정확도·최종 확정을 따로 기록한다. 자료가 없으면 추측하지 않고 검색/수동 확인으로 이어져야 한다. 이 표본 계획은 실행되지 않았다.
- **1차 공개 방식 제안:** 지도·검색과 수동 확정이 유용한지 소규모 검증한 뒤 출시한다. 자동 분석을 반드시 넣어야만 1차가 끝난다고 가정하지 않는다. 자동 저장을 홍보하려면 정확도·데이터 접근·비용 검증을 추가 출시 조건으로 삼는다.
- **Instagram DM 자동 수신:** 공유 메뉴로 받은 URL 저장과 다른 기능이다. 공식 API 권한·수신 가능한 계정/데이터·심사·웹훅·재전송·삭제를 별도로 실증해야 한다. 이번 점검에서는 Meta의 현행 권한을 재검증하거나 실제 연동하지 않았다. 모든 개인 계정 DM을 읽는 기능으로 약속하지 않는다. 1차 수동 개인 앱의 출시 조건에서는 제외하는 제안이다.

## 마케팅·수익화에서 남은 작업

1. **실제 사용자 검증:** 목표 고객 5~10명에게 저장·지점 확인·며칠 뒤 재열람 과제를 계획하고, 수동 확정의 부담과 재사용 이유를 확인한다. 이후 실제 테스터 모집과 연락은 별도 실행이다.
2. **출시 소재:** 작동하는 출시 빌드의 스크린샷·Galaxy 공유 시연·소개문·15초 영상 3종을 만든다. 기존 정적 목업 화면을 실제 로그인/DM/자동 분석 기능의 증거로 사용하지 않는다. 본인 소유 또는 사용 허락된 콘텐츠를 사용한다.
3. **유입 경로:** 본인 콘텐츠·규칙상 허용되는 커뮤니티 모집·Galaxy 공유 사용법을 먼저 검증한다. 게시·크리에이터 연락·광고 구매는 아직 실행되지 않았다.
4. **관측과 개인정보:** 첫 확정 저장, 재열람/길찾기, D7, 실제 광고 노출·eCPM·API 비용을 정의한다. 수집 도구/목적/동의·보존을 정하고, URL·장소명·메모·좌표 없이 필요한 집계만 구현한다. 현재 측정 시스템과 실제 성과 데이터는 없다.
5. **유료 확대:** 관측한 유지율·활성 사용자 획득비·생애 광고 매출에서 지도/분석 등 변동비를 뺀 금액을 비교한 뒤 결정한다. 기존 문서의 단가·목표·예산은 가정이며 실제 매출 예측이 아니다. 소규모 출시 자체를 큰 표본의 유지율 목표 달성까지 무조건 미루지는 않는다.

광고를 넣으면 수익이 보장되는 단계는 아니다. 우선 목표는 저장 후 다음 외출 때 다시 여는 사용자 확보다. 광고 실패와 비용 초과를 막는 개발은 공개 전에 하고, 유료 마케팅 확대는 실측 결과가 생긴 뒤 판단한다.

## 계정·공유 기능의 잔여 작업과 2차 간편 로그인

아래는 전체 서비스의 후속 항목이다. 기본 이메일 로그인·계정 생명주기의 앱 구현/로컬 공식 인증 검사는 AUTH-02에서 진행했고 운영 활성화는 남았다. 카카오/구글 간편 로그인은 2차다. 개인 원본 클라우드 복구·동기화는 제외한다. 상대 연결/공유는 아직 미구현이며 AUTH-01 정책과 후속 구현 브리프를 따른다.

| 묶음 | 필요한 작업·검증 |
|---|---|
| 인증·서버 | 제공자/DB/지역·비용·데이터 정책 확정, 실제 로그인/취소/재인증/토큰 만료·계정 전환, 서버 신원 검증·운영 설정 |
| 기기 내 계정 소유 영역 전환 | 사용자 동의·중복/재시도·취소/오프라인에서 원본 보존, 계정별 로컬 분리, 로그아웃/다른 계정에서 캐시 노출 방지. 개인 원본 서버 이전/동기화 없음 |
| 개인·2인 공유 맵 | 개인 기록 비공개, 선택한 장소만 복제, 맵별 독립 편집, 서버에서 읽기/저장/복제 직전 인가, 권한 종료와 경합 검사 |
| 연결 코드 | 만료/취소/사용 완료·재발급 무효화·속도 제한·단일 사용의 원자성, 로그인+연결 확인 전 기록 비공개 |
| 탈퇴·보존 | 앱 내/외부 웹 계정 삭제 요청, 계정 관련 서버·수탁 데이터 삭제/보존 근거, 공유 기록·마지막 참여자·복제본 처리 정책, 삭제/재가입 검증 |
| 출시·보안 | 다른 계정 접근·권한 회수·동시 초대/수정·복구·서비스 장애 검사, 실제 개인정보 문구/데이터 보안 신고와 스토어 자료 갱신 |
| 2차 간편 로그인 | Google/Kakao 실제 인증·같은 UID에 로그인 수단 연결/해제·다른 계정 충돌, 개인 원본 로컬 전용 유지 |

계정 생성 기능을 제공하면 계정 삭제 요청 경로도 앱 안과 외부 웹에 제공해야 한다. 이 요건은 로그인 없는 로컬 기록 전체 삭제와 구분한다. DM 연동은 실제 로그인만 붙이면 따라오는 기능이 아니다. [Play 계정 삭제 요건](https://support.google.com/googleplay/android-developer/answer/13327111?hl=en)

## 권장 실행 순서와 출시에 필요한 증거

1. **지금 병행:** 계정 유형/준비 상태·기기/테스터·문의처/도메인·예산 확인, 실제 입력 표본과 지도 이용 조건 실증. 제출 초안을 준비한다.
2. **핵심 개발:** L01 지도·검색·좌표와 데이터 마이그레이션, L02 첫 저장·재열람 UX. 자동 분석을 어디까지 약속할지 실증 결과로 정한다.
3. **수익·운영 개발:** L03 광고 테스트·동의/실패 처리, L04 처리방침·SDK/신고, L09 비용/문의·오류 대응을 함께 완성한다.
4. **출시 후보 검사:** L05 Galaxy와 최종 release/AAB 검사, L06 서명/설치/업데이트. 발견한 유실·오저장·광고 차단 문제를 해소한다.
5. **스토어 비공개 테스트:** L07 등록 자료와 적용되는 테스트를 진행하고 수정한다. 필요한 프로덕션 접근·심사를 통과한 뒤 소규모 공개를 진행한다.
6. **수익 활성화·검증:** L08 스토어 연결·app-ads.txt·AdMob 검토/정산을 마친 상태에서 실제 게재를 확인한다. 심사 중에는 광고 없는 공개와 수익 가능한 공개를 구분한다. 광고 수익·비용·재사용을 측정한 뒤 마케팅을 확대하고 2차를 개발한다.

출시 가능 판정에는 최종 빌드 SHA와 AAB·서명/업데이트 증거, 실제 Galaxy 검사표, 처리방침/지원 URL·신고, 해당되는 테스트/스토어 승인 기록, 운영 담당/비용 통제가 필요하다. 광고 수익 가능 판정에는 광고 게재·정산·소유권/앱 검토 확인이 추가된다. 실제 승인·게재를 확인하기 전에는 완료로 표시하지 않는다.
