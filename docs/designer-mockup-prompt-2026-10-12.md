# 가자함 (Gajaham) 목업 제작 요청 프롬프트

아래 요구사항에 따라 **가자함의 모바일 웹 서비스 목업과 주요 사용 흐름을 연결한 프로토타입**을 제작해주세요. 화면 구성, 동작, 공개 범위, 예외 상태, 제작 범위와 미정 사항은 이 문서 안에 모두 정리되어 있습니다. 별도 기획서나 외부 자료를 찾아 내용을 보충할 필요가 없습니다. 여기에 없는 기능·계정·요금·성과를 추가하거나, 미정인 정책을 확정된 서비스 안내처럼 표현하지 마세요.

## 1. 작업 범위와 요구사항의 구분

- 기본 제작 범위는 **첫 외부 베타: V0.1의 DM·지도 기능 + V0.5의 기본 카드와 최소 공동 선택**입니다. 실제 개발·계정 연동·추출 품질 검증·제공 시점은 확정되지 않았습니다.
- 초기 국내 장소와 한 생활권 중심의 베타라는 기획 방향을 유지합니다. 실제 첫 지원 지역은 미정이므로 전국·해외 지원을 확정된 서비스 범위처럼 표시하지 않습니다.
- **P0는 첫 베타의 필수 제작 범위**입니다. 아래 8개 화면군의 기본 동작과 정상·빈·대기·보완·실패·부분 완료 상태를 모두 포함합니다.
- **P1은 첫 베타 보강안**입니다. 여러 장소 자동 분리, 상세 카드 보강, 지역·예산·시간 조건으로 후보 좁히기를 기본 흐름과 구분해 표현합니다.
- **후속 버전은 현재 제공 기능이 아닙니다.** 블로그 분석은 V0.8, 조건별 자동 추천은 V1.0, 코스는 V1.5, 취향 기반 재추천은 V2.0의 확장 범위로 분리합니다.
- 사용자 요구는 DM 전달 수집, 맛집·카페·놀거리의 지도 표시, 게시물 내용·추천 메뉴의 정보 카드, 개인 맵 유지, 코드 연결 공유 맵, 초기 선택 복제, 이후 양방향 복제, 신규 등록 맵 선택, 이후 블로그 확장입니다.
- 맵 개수·최초 저장 기본값·복제 세부 동작은 **초기 기획 제안**입니다. 이 문서에 적힌 안으로 목업을 만들되 확정 운영 정책으로 설명하지 않습니다.
- `기획 제안 / 초기안 / 미정 / 검증 필요 / P1 / 후속 버전`의 구분은 화면 밖의 디자인 주석에 표시합니다. 미정 사항을 임의로 결정하지 마세요.

서비스명은 **가자함**, 영문은 **Gajaham**으로 사용합니다. 처음 소개할 때는 **가자함 (Gajaham)**으로 병기할 수 있습니다. 로고·색상·서체는 미정이므로 시각 디자인을 제안하되 확정된 브랜드 가이드로 설명하지 마세요.

## 2. 서비스의 핵심 경험

사용자가 인스타그램 게시물·릴스를 **서비스 계정에 개별 DM으로 전달**하거나 모바일 웹에 링크를 입력하면, 확보 가능한 자료에서 장소와 게시물 내용을 정리해 사용자가 선택한 맵에 보관하는 서비스입니다. 맛집·카페·놀거리를 지도와 목록으로 다시 보고, 원문에 있는 추천 메뉴와 저장 맥락을 확인하며, 공유 맵에서는 두 사람이 방문 후보를 수동으로 고릅니다.

기본 흐름은 다음과 같습니다.

**발견 → DM 전달 또는 웹 링크 입력 → 본인 확인·저장 대상 확인 → 분석 또는 사용자 보완 → 장소 카드·지도에서 재조회 → 공유 맵에서 후보 비교·최종 선택 → 길찾기 → 방문 표시**

개인 사용만으로도 저장과 재조회가 가능해야 합니다. 상대방의 가입·공유 연결을 첫 저장의 필수 조건으로 만들지 마세요. 첫 제공 형태는 모바일 웹이며 네이티브 앱 설치를 요구하지 않습니다.

## 3. 반드시 유지할 동작과 공개 범위

1. **개인 맵과 공유 맵을 함께 유지합니다.** 코드로 연결해도 개인 맵을 공유 맵으로 바꾸거나 개인 기록을 자동 공개하지 않습니다. 초기 기획 제안은 사용자당 개인 맵 1개·활성 공유 맵 1개·공유 맵 참여자 최대 2명입니다. 여러 개인 맵, 여러 활성 공유 맵, 3명 이상 그룹은 추가하지 마세요.
2. **공유 연결과 DM 계정 연결을 구분합니다.** 공유 연결 코드는 두 서비스 사용자를 공유 맵에 연결하는 수단입니다. 각자의 인스타그램 DM 발신자 확인은 별도로 진행합니다. 코드 입력만으로 상대의 기록을 바로 열거나 인스타그램 계정까지 연결된 것으로 표시하지 마세요.
3. **연결 시 복제는 각자가 선택합니다.** `지금 복제 안 함 / 선택한 장소 복제 / 전체 장소 복제`를 제공합니다. 자신의 개인 장소만 선택하며 상대방의 개인 장소 목록은 보이지 않습니다. 한 사람이 초기 복제를 마칠 때까지 상대방의 사용을 막지 않습니다.
4. **연결 후에도 양방향 복제를 제공합니다.** 개인 맵 → 공유 맵, 공유 맵 → 내 개인 맵으로 카드 1개·여러 장소 선택·전체 장소를 복제할 수 있습니다. 다른 참여자의 개인 맵은 대상에 나타나지 않습니다.
5. **복제는 원 항목을 유지합니다.** 복제 후 메모·수정·위치 보정·방문 상태·삭제는 각 맵에서 독립적으로 적용됩니다. 이동이나 실시간 동기화처럼 표현하지 마세요. 이미 분석한 결과의 복제에 새 분석을 요구하지 않습니다.
6. **개인 추가 정보는 별도로 선택합니다.** 공유 맵으로 복제할 때 개인 메모·직접 올린 사진·개인 방문 기록은 기본 선택 해제합니다. 전체 장소 복제도 이 확인을 생략하지 않습니다. 공유 맵의 메모·사진을 내 개인 맵에 복제할 때는 읽을 권한이 있는 항목 중 선택합니다. 관심 표시·공동 약속·상대방 개인 평가는 복제 대상에 넣지 않습니다.
7. **중복 처리는 맵 안에서 적용합니다.** 대상 맵에 같은 지점이 있으면 누락된 출처를 추가하고 기존 사용자 수정·메모·방문 상태를 보존합니다. 서로 다른 지점은 별도 장소로 유지합니다. 위치 미확정 항목은 미확정 상태로 복제합니다. 다른 맵에 같은 장소가 있다는 이유로 자동 공유하지 않습니다.
8. **신규 등록 대상을 명확히 보여줍니다.** 연결 전에는 개인 맵을 제공합니다. 연결 후 저장 선택지는 초기안인 `개인 맵 / 공유 맵 / 둘 다`를 사용합니다. 대상 맵과 누구에게 보이는지를 등록 전에 확인할 수 있어야 합니다.
9. **웹의 현재 맵과 DM 기본값은 별개입니다.** 웹 입력은 현재 보고 있는 맵을 기본 대상으로 표시하고 변경할 수 있습니다. DM의 최초 기본값은 개인 맵이라는 기획 제안을 적용하며 설정에서 변경합니다. 웹의 맵 전환이 DM 기본값을 바꾸지 않습니다. DM 기본값 변경은 이후 접수 건에만 적용됩니다.
10. **결과는 실제 완료 기준으로 표시합니다.** 접수 완료와 저장 완료를 구분합니다. `둘 다` 저장과 대량 복제는 대상별 결과를 표시하고 실패한 대상·항목만 다시 처리할 수 있게 합니다. 원래 요청한 대상과 실제 완료 대상이 다르면 구분합니다.
11. **권한 종료 후 공유 맵을 사용할 수 없습니다.** 연결 종료 후 개인 맵과 이미 개인 맵에 복제한 기록은 유지합니다. 종료된 공유 맵에는 저장·복제할 수 없으며 옛 결과 링크로 접근할 수도 없습니다. 처리 중 권한이 종료되면 개인 처리함에서 대상 변경을 요청합니다.
12. **재분석이 사용자 기록을 덮어쓰지 않습니다.** 자동 추출 정보와 사용자 메모·수정은 구분합니다. 비공개 원본 맵의 이름이나 다른 개인 기록이 공유 카드·복제 이력에 노출되지 않도록 합니다.

## 4. 제작할 8개 화면군

아래 8개 화면군을 모두 제작합니다. 하위 화면·모달·하단 패널의 배치는 디자인으로 제안할 수 있지만, 행동과 조건을 생략하거나 새 기능을 추가하지 마세요.

### 4.1 시작·연결

포함할 장면:

- 서비스 설명과 개인 맵 시작. 개인 이용자가 첫 링크를 저장할 수 있는 진입을 제공합니다.
- 최초 DM에서 전달받은 모바일 웹 연결 안내, 본인 계정 확인, 개인 맵과 저장 대상 확인. 본인 확인 전 입력은 비공개 임시 접수 상태로 보여줍니다.
- `함께 쓰기 → 연결 코드 만들기`와 상대방의 코드 입력 화면.
- 상대방이 로그인한 뒤 코드를 입력하고 연결 대상 사용자를 확인하는 화면. 이미 개인 맵에 기록이 있어도 연결 가능합니다.
- 연결 완료 후 공유 맵이 생기고 개인 맵은 유지되는 결과. 이어서 각자의 초기 복제 선택으로 연결합니다.
- 코드의 사용 가능·만료·취소·사용 완료 상태, 코드 취소와 재발급. 재발급 시 이전 코드가 무효가 되는 상태도 표현합니다.
- 이미 활성 공유 맵에 참여 중인 경우 기존 연결을 안내하는 상태. 새 연결로 자동 교체하지 않습니다.

실제 서비스 인스타그램 아이디와 로그인 수단은 미정입니다. 시연에서는 `서비스 계정`, `로그인`, `본인 확인`처럼 중립적으로 표시하고, 실제 계정명·인증 방식·코드 형식·만료 시간은 화면 밖에 `미정`으로 주석 처리하세요. 일반 사용자에게 프로 계정 전환을 요구하지 마세요.

### 4.2 초기 복제·다른 맵에 복제

포함할 장면:

- 초기 복제의 `지금 복제 안 함 / 선택한 장소 복제 / 전체 장소 복제` 선택.
- 자신의 개인 장소 목록에서 복제할 장소를 선택하는 화면. 상대방 개인 장소 목록은 제공하지 않습니다.
- 연결 후 상세 카드에서 1개 복제, 지도·목록에서 선택 복제와 전체 복제로 진입하는 화면.
- 복제 미리보기: 원래 맵과 대상 맵, 선택한 장소, 포함할 정보, 개인 메모·사진·방문 기록의 선택 여부를 확인합니다. 비공개 원본 맵 이름은 본인에게 확인시키되 상대방에게 노출하지 않습니다.
- 공유 맵으로 복제할 때 개인 추가 항목이 기본 해제된 상태. `전체 장소` 선택이 개인 정보까지 모두 포함한다는 의미가 되지 않도록 합니다.
- 원래 항목이 남고 복제 후 각 맵에서 따로 관리된다는 안내.
- 새 장소 추가, 기존 같은 지점에 출처 추가, 일부 실패를 구분한 결과와 실패 항목 재처리.

초기 복제를 건너뛰어도 나중에 같은 행동을 사용할 수 있게 합니다. 복제 결과의 관심·약속·평가는 대상 맵에서 새로 관리하며, 복제 이력은 원 저장자와 복제한 사람을 구분할 수 있어야 합니다.

### 4.3 링크 등록

포함할 장면:

- URL 입력과 선택한 대상 맵·공개 범위.
- 연결 전 개인 맵 저장, 연결 후 `개인 맵 / 공유 맵 / 둘 다` 선택.
- 웹에서 현재 맵을 기본 대상으로 표시하되 등록 전에 바꿀 수 있는 상태.
- 접수 안내와 처리함으로 이어지는 흐름. 접수만 된 상태를 지도 저장 성공으로 표현하지 않습니다.
- 완료 결과에 실제 등록한 맵 이름과 결과 표시.
- `둘 다`에서 한쪽만 성공한 결과와 실패한 쪽만 재처리하는 행동.

첫 베타에서 블로그 분석을 이미 지원하는 것처럼 소개하지 않습니다. 아직 지원하지 않는 출처를 입력한 경우 분석 미지원과 링크 보관·원본 확인을 구분해 안내합니다.

### 4.4 개인·공유 지도와 목록

포함할 장면:

- 현재 맵 이름과 개인·공유 맵 전환. 공유 연결 전에는 개인 맵을 사용합니다.
- 같은 맵의 지도·목록 전환.
- 기본 카테고리 `맛집 / 카페 / 놀거리`, 장소명·지역 검색, 방문 상태와 보낸 사람 기준의 조회.
- 위치가 확정된 장소의 지도 핀. 핀을 누르면 하단에 카드 요약을 열고 자세한 내용은 별도 상세 화면으로 이동합니다.
- 미확정 장소를 목록에서 찾을 수 있는 상태. 임의 좌표로 핀을 만들지 않습니다.
- 현재 맵에 링크 등록, 장소 선택·전체 복제 진입.
- 개인 맵·공유 맵의 빈 상태, 검색 결과 없음, 지도 로딩 실패 상태. 지도에 문제가 있어도 목록과 원본 링크는 이용할 수 있어야 합니다.

개인 맵의 장소를 공동 후보에 넣는 흐름은 공유할 내용을 확인한 뒤 공유 맵으로 복제하는 절차를 거칩니다. 상대방 개인 맵을 여는 탭이나 공개 지도 링크 기능은 추가하지 마세요.

### 4.5 처리함

기본 처리 흐름은 다음과 같습니다.

`접수 → 연결 대기 또는 분석 중 → 저장 완료 / 일부 완료 / 확인 필요 / 분석 실패`

포함할 내용과 행동:

- 원본 링크, 선택한 저장 대상, 대상별 처리 상태와 실패 이유.
- 연결 대기, 분석 중, 확인 필요, 분석 실패, 일부 완료의 장면.
- 등록 전 항목별 저장 대상 확인·변경. 이미 저장 완료된 항목은 다른 맵에 복제하는 흐름으로 연결합니다.
- 동명 장소·지점이 모호할 때 후보와 차이를 비교하고 장소를 선택하거나 검색해 수정하는 화면.
- 읽을 수 없는 콘텐츠의 본문·사용자 캡처 보완 또는 장소 검색. 장소 없는 게시물은 수동으로 장소를 연결할 수 있게 합니다.
- 사용자 보완 후 재분석 또는 직접 저장, 재시도, 처리 항목 삭제.
- 여러 장소 중 일부만 확인된 결과와 미확정 목록. 자동 분리가 미완성이어도 `여러 장소 확인 필요`를 알리고 장소를 추가할 수 있어야 합니다.
- 처리 지연·DM 회신 제한 시 웹에서 상태를 확인하는 안내. 임의의 예상 완료 시간·재시도 횟수를 표시하지 않습니다.
- 분석 중 공유 권한이 종료된 항목의 대상 변경 요청과 맵별 부분 실패.

분석 실패·접근 불가·메뉴 없음·위치 미확정을 같은 상태로 뭉뚱그리지 마세요. 장소는 확인됐지만 메뉴 근거가 없는 경우에는 메뉴를 비워두고 장소 저장을 완료할 수 있습니다.

### 4.6 장소 상세

포함할 정보:

- 현재 맵 이름, 장소명·지점·주소·카테고리와 위치 확인 상태.
- 표시 가능한 대표 이미지 또는 이미지 없는 대체 카드.
- 원문을 바탕으로 한 짧은 소개, 게시물 추천 메뉴 또는 언급 메뉴, 확보한 추천 이유·방문 팁.
- 원본 링크, 콘텐츠 출처, 보낸 사람·저장자, 저장 날짜, 가능한 범위의 게시일·가져온 시각·근거.
- 자동 추출과 사용자 입력·수정을 구분한 표시, 현재 맵의 메모와 방문 상태.
- 같은 장소에 연결된 여러 참고 글. 새 출처가 기존 메모·사용자 수정을 덮어쓰지 않는 상태.

주요 행동:

- 정보·카테고리·메모 수정, 위치 수정, 원본 열기, 외부 지도 앱 길찾기.
- 다른 맵에 복제, `가고 싶어`, 공유 맵에서 `이번 약속 후보`, `다녀왔어요`.
- 해당 맵의 저장 항목 삭제와 휴지통 복구 흐름.

지도 제공자와 길찾기 서비스는 미정이므로 특정 업체를 확정된 제공자로 표시하지 마세요. 공유 맵에서 두 사람이 추가·수정·삭제할 수 있고 저장자·수정자·삭제자·복제자를 구분한다는 원칙을 유지합니다. 개인 맵 메모는 본인만 봅니다. 공유 맵의 ‘각자 메모’를 새로 만든 비공개 메모 기능으로 해석하지 말고, 세부 공개 범위가 필요한 곳은 기획 확인 주석으로 남깁니다.

### 4.7 이번 약속

포함할 장면:

- 공유 맵에 저장한 장소를 대상으로 한 수동 후보 선택.
- 최대 3개 후보, 두 사람의 관심 표시, 장소·위치·원문 메뉴·메모의 비교.
- 후보 추가·교체, 최종 장소 1개 선택, 선택 결과와 선택 변경.
- 최종 장소 상세와 외부 길찾기, 방문 후 `다녀왔어요` 표시로 이어지는 흐름.
- 후보가 없는 상태와 개인 장소를 공유 맵에 복제한 뒤 후보에 추가하는 흐름.

첫 베타에서는 조건별 자동 추천·데이트 코스·취향 모델을 넣지 않습니다. ‘최대 3곳’은 유지하되 공동 전체 기준인지 각자 기준인지는 미정입니다. 최종 선택에 두 사람의 동의가 필요한지, 누구에게 확정 권한이 있는지, 방문 표시의 단위가 무엇인지는 디자인 주석으로 남기세요. 임의의 승인 절차·약속 날짜·취소 정책·약속 이력 시스템을 추가하지 마세요.

### 4.8 맵·설정

포함할 장면:

- 개인 맵과 현재 공유 맵의 구성, 공유 구성원과 연결 코드 상태.
- 코드 생성·입력·취소·재발급 진입과 DM 계정 연결 상태 확인.
- 사용자별 DM 기본 저장 위치 `개인 맵 / 공유 맵 / 둘 다`. 공유 맵 또는 둘 다를 선택할 때 이후 전달 장소가 상대방에게 보인다는 안내.
- 기본값 변경은 이후 접수 항목에 적용되고 처리 중 항목의 대상은 개별 화면에서 바꾸는 동작.
- 접근 가능한 맵의 구조화된 기록 내보내기. 장소명·주소·메모·원본 URL·상태 등 기본 기록을 대상으로 하며 원본 미디어 전체 다운로드·영구 보관을 약속하지 않습니다. 파일 형식은 임의로 확정하지 마세요.
- 맵별 휴지통과 저장 항목 복구. 다른 맵의 복제본이 함께 삭제되지 않는 상태.
- 공유 맵 나가기·연결 종료 안내. 접근 종료 시점과 남는 공동 기록을 안내할 자리를 두고, 종료 전에 접근 가능한 공유 장소를 내 개인 맵에 복제할 선택을 제공합니다.
- 종료 후 개인 맵·개인 복제본 유지, 종료된 공유 맵 접근 불가, 유효하지 않은 DM 기본 대상을 개인 맵으로 변경한 안내.
- 기록 삭제와 계정 탈퇴 진입. 영구 삭제·보관 기간·마지막 참여자 처리 등 미정 정책은 확정 수치나 문구 없이 디자인 주석으로 표시합니다.

새 상대와 연결하면 새로운 공유 맵을 만들며 이전 공유 기록을 자동 공개하지 않습니다. 나머지 참여자의 공유 기록을 임의로 모두 삭제하지 않습니다. 본인의 공유 연결 종료가 상대방의 DM 계정 연결을 바꾸는 것으로 표시하지 마세요.

다음 상태는 위 화면군의 변형으로 제작합니다. 필요 없는 새 메뉴를 만들어 분리하지 않아도 됩니다.

## 6. 정보 카드와 시연 데이터 작성 규칙

스냅샷은 **장소와 게시물 내용을 빠르게 기억하는 정보 카드**입니다. 원본 영상의 영구 복제, 자동 캡처 보장, 원문 삭제 후 재생 기능으로 표현하지 마세요.

- 단순 등장 메뉴와 작성자가 추천한 메뉴를 구분합니다. 추천 근거가 없으면 `언급 메뉴`로 표시합니다. 메뉴가 없으면 비워두거나 `메뉴 정보 없음`으로 표시합니다.
- 추천 이유와 방문 팁은 게시물 작성자의 표현·경험임을 알 수 있게 합니다. 이를 서비스가 검증한 현재 사실로 바꾸지 않습니다.
- 가격·영업시간·행사 기간은 원문에 있을 때만 출처와 시점을 붙입니다. 목업을 채우려고 금액·시간·기간을 만들지 마세요. `위치 확인됨`이 운영 정보 최신 확인을 의미하지 않도록 합니다.
- 이미지가 없을 때 사용할 대체 카드도 제작합니다. 사용자 캡처 보완과 자동 이미지 확보를 같은 기능으로 표현하지 않습니다.
- 날짜·주소·원본 URL 등 실제 정보가 제공되지 않은 필드는 비우거나 명확한 시연용 자리표시자를 사용합니다. 실제 가게의 최신 정보로 오해될 내용을 만들지 마세요.
- 서로 다른 글의 가격·메뉴 정보가 충돌하면 출처별로 구분합니다. 한 값을 임의로 골라 최신 정보라고 표시하지 않습니다.
- 사용자 A·사용자 B는 시연용 역할 표기입니다. 실제 사용자명·인스타그램 아이디·공식 운영 계정으로 제시하지 않습니다.
- 가격 실험, 베타 참가자 수, 내부 완성률 목표, 경쟁사의 기능·요금은 제품 성과나 가자함의 상품 정보로 가져오지 않습니다.

아래 예시를 정보 카드 구성의 기준으로 사용하세요. **실제 가게 정보가 아닌 화면 예시**라는 사실을 목업의 주석에 표시합니다.

> **예시 카페 · 성수점**  
> 카페 · 서울 성동구 · 위치 확인됨  
> 테라스 분위기와 피스타치오 음료를 소개한 게시물  
> **게시물 추천 메뉴:** 피스타치오 라테 — 원문 추천 표현 확인  
> **방문 팁:** 주말 대기 언급 — 게시물 작성자의 경험  
> **등록 맵:** 우리 공유 맵  
> **우리 메모:** 서울숲 산책하고 가기  
> **출처:** 인스타 게시물 1개 · 보낸 사람 A · 저장 날짜  
> **행동:** 가고 싶어 / 이번 약속 후보 / 다른 맵에 복제 / 위치 수정 / 원본 / 길찾기

이 예시에서도 제공되지 않은 상세 주소·좌표·가격·영업시간·원본 URL·실제 날짜는 추가하지 마세요.

## 7. 첫 베타 보강안과 후속 버전 구분

첫 베타 P1은 기본 흐름과 구분해 표시합니다.

- 한 게시물의 여러 장소 자동 분리. 다만 일부 장소만 저장된 사실과 추가 확인 요청은 P0부터 드러나야 합니다.
- 확보 가능한 이미지·OCR·추천 이유·방문 팁·필드별 출처를 보강한 상세 카드. 기본 카드·원본 연결·이미지 없는 상태를 이 보강 기능의 완료 여부에 종속시키지 않습니다.
- 지역·예산·시간 조건으로 후보를 좁히는 보강안. 이를 V1.0의 조건별 자동 추천과 혼동하지 않습니다.

후속 확장 화면을 제안한다면 별도 구역과 버전 주석으로 분리하세요. 첫 베타의 활성 메뉴와 현재 지원 안내에 섞지 않습니다.

| 버전 | 후속 확장 범위 |
|---|---|
| V0.8 | 지원하는 블로그 URL을 DM·웹으로 입력, 같은 장소에 출처 추가, 읽기 실패 보완. 네이버 블로그는 첫 검증 후보이며 모든 글 지원은 미확정 |

## 8. 임의로 만들지 말아야 할 내용

- 실제 서비스 인스타그램 계정명, 특정 소셜 로그인 제공자, 인증 방식, 연결 코드 길이·유효 시간.
- 요금제 이름, 정식 가격표, 무료 저장·분석 한도, 체험 기간, 무제한 제공, 구독·추가 구매·결제 화면. **월 3,000원은 결제 실험 가설**이며 정식 요금이 아닙니다. 해당 금액에 제공할 기능·분석량·기간·결제 주체·해지 조건도 미정이므로 목업에 판매 조건으로 표시하지 않습니다.
- 저장·분석 시간 보장, 정확도·성공률 보장, 실제 사용자 수·후기·평점, 국내 최초·유일·최고 주장.
- 개인 DM 전체 읽기, 과거 대화 자동 가져오기, 커플 그룹 DM에 봇을 넣는 방식, 상대방 인스타그램 아이디만 입력해서 연결하는 방식.
- 공개 추천 피드, 공개 지도 공유, 장문 채팅, 상점 광고, 예약·결제 대행, 해외 장소 확대, 첫 베타의 자동 데이트 코스·취향 추천.

- 확정되지 않은 공동 승인 절차, 약속 일정·취소·이력 정책, 복구 기간, 데이터 보관 기간, 영구 삭제 범위.
- 사용자에게 일반 인스타그램 계정을 비즈니스·크리에이터 계정으로 바꾸도록 요구하는 안내. 서비스 운영 계정 조건과 일반 이용자의 조건을 섞지 않습니다.

## 9. 디자인과 납품 방식

- 모바일 웹에서 장소·메뉴·메모를 읽기 쉽게 구성하고, 지도 핀 → 하단 요약 → 상세의 흐름을 유지합니다.
- 현재 맵, 저장·복제 대상, 공개 범위, 처리 결과는 관련 행동 가까이에 표시합니다. 색상만으로 상태를 구분하지 말고 문구를 함께 사용합니다.
- 메뉴·버튼·용어는 일관되게 사용합니다. `함께 쓰기`, `개인 맵`, `공유 맵`, `둘 다`, `다른 맵에 복제`, `처리함`, `이번 약속`을 임의의 다른 기능 개념으로 바꾸지 않습니다.
- 일반 화면에는 사용자가 행동을 결정하는 데 필요한 설명을 넣습니다. API·토큰·권한 구현·비용 계측 등 제작 판단용 설명과 `기획 제안 / 미정 / P1 / 후속 버전` 표시는 화면 밖의 디자인 주석으로 정리합니다.
- 8개 화면군의 정상·빈·대기·보완·실패·부분 완료 상태를 제공합니다. 화면 프레임 수는 필요한 상태에 맞춰 정하되 필수 흐름을 한 장의 정적 화면으로 생략하지 않습니다.
- 프로토타입에는 아래 사용 흐름을 연결합니다.

  1. 최초 DM 접수 → 본인 확인 → 개인 맵 저장 → 지도·상세 재조회.
  2. 기존 개인 맵이 있는 두 사용자 → 코드 연결 → 각자의 초기 복제 선택 → 개인·공유 맵 전환.
  3. 웹 링크 입력 → 저장 대상 선택 → 실제 맵별 결과 확인, 둘 다 저장의 부분 실패 재처리.
  4. 개인→공유와 공유→내 개인 복제 → 메모·사진 선택 → 미리보기 → 중복·부분 실패 결과 확인.
  5. 공유 맵의 관심 표시 → 수동 후보 최대 3곳 → 비교·최종 선택 → 길찾기 → 방문 표시.
  6. 확인 필요 항목 → 장소 검색·보완 → 저장, 처리 중 공유 권한 종료 → 대상 변경.
  7. 항목 삭제·휴지통 복구·내보내기, 공유 종료 전 개인 복제 → 종료 후 개인 기록 유지 확인.

- 각 화면에는 적용한 동작과 정책 확인 사항을 주석으로 붙입니다. 미정인 내용은 임의로 완료하지 말고 **확인할 쟁점과 그 결정이 필요한 화면**을 함께 남기세요.
