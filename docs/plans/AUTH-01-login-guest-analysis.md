## 1. 사용자 확정과 이번 범위

사용자가 기본 로그인 **이메일+비밀번호**, 간편 로그인 **카카오·구글 등은 2차**, 비로그인 개인 이용 허용·상대 계정 연결 불가를 확정했다. 복구 범위 질문에는 **‘로그인 여부와 관계없이 개인 기록은 앱 삭제 시 복구 불가’**를 선택했다. 따라서 이전의 로그인 사용자 개인 기록 클라우드 복구 제안은 폐기한다.

이번 산출물은 기능·정책·설계·검증 분석이다. 실제 인증 화면/SDK·서버·계정 연결을 구현하거나 운영 프로젝트를 만든 결과가 아니다. 새 로그인 기능을 목업 로그인 상태값으로 대신하지 않는다.

## 2. 기능 구분

| 기능 | 비로그인 개인 이용 | 이메일 로그인 이용 | 2차 간편 로그인 |
|---|---|---|---|
| 공유 메뉴/직접 입력·개인 장소·메모·방문·휴지통 | 이용 가능, 기기 내 보관 | 이용 가능, 기기 내 보관 | 같은 로컬 보관 정책 |
| 앱 삭제 후 개인 원본 복구 | 불가 | 불가 | 불가 |
| 개인 기록의 서버 동기화·파일 백업/가져오기 | 제공하지 않음 | 제공하지 않음 | 제공하지 않음 |
| 상대 계정 연결·초대 코드 발급/사용·공유 맵 접근 | 차단, 로그인 안내 | 이메일 확인·유효 인증·서버 권한 확인 후 제공하는 설계 | 같은 권한 규칙 |
| 계정 인증·비밀번호 재설정·탈퇴 | 서비스 계정 없음 | 필요 | 같은 서비스 UID에 소셜 수단 추가/관리 |
| 카카오·구글 로그인 버튼 | 1차에 작동하는 기능처럼 노출하지 않음 | 1차 미제공 | 실제 제공자 인증·서버 검증 후 제공 |

로그인 없는 이용은 Firebase 익명 계정을 자동 생성하는 방식으로 대체하지 않는다. 지도 검색/광고를 도입하면 해당 서비스 통신과 고지는 별도이며, 비로그인이라는 이유로 모든 네트워크 처리가 없다고 표현하지 않는다.

## 3. 개인 기록·계정·공유 사본의 경계

**개인 기록:** 개인 장소·원본 URL·저장 이유/메뉴·방문·처리함·휴지통의 개인 원본. 로그인 상태에도 로컬 DB에만 저장하며 서버 동기화/복구 API를 두지 않는다. 사용자에 대한 상세 서버 이벤트·오류 로그에도 개인 원문을 싣지 않는다.

**계정 정보:** 서비스 UID, 이메일/인증 상태, 로그인 수단, 계정 상태다. 인증 제공자와 서버에서 필요한 범위로 관리한다. 비밀번호 원문을 앱 DB나 자체 로그에 저장하지 않는다. 비밀번호를 재설정해도 UID가 유지되는 같은 계정이면 현재 설치에 남은 그 계정의 로컬 기록을 읽을 수 있다. 앱 삭제 뒤에는 읽을 로컬 기록이 없다.

**공유 사본:** 사용자가 공유 대상으로 확인한 장소만 별도 서버 데이터로 만드는 제안이다. 개인 맵 전체·개인 기록 백업을 자동 업로드하지 않는다. 공유 사본은 맵별 독립 편집 규칙을 지킨다. 앱 삭제 뒤 로그인 시 유효한 연결/공유 맵을 다시 보는 동작은 개인 원본 복구와 다르다. 공유→개인 복제는 명시적 새 저장이며 원래 개인 메모·방문·휴지통을 되살리는 기능으로 만들지 않는다.

공유 데이터의 구체적인 보존 기간, 탈퇴자의 작성자 식별자/개인 메모 제거, 마지막 참여자 종료 처리는 후속 공유 구현의 정책 결정 항목이다. ‘개인 기록 복구 불가’를 근거로 상대방의 공유 사본까지 앱 삭제 즉시 지우는 정책을 추정하지 않는다.

## 4. 주요 이용 흐름

1. **첫 실행:** ‘이메일로 로그인’과 ‘로그인 없이 시작’을 제공한다. 양쪽에 ‘개인 기록은 이 기기에만 저장돼요. 로그인해도 백업되지 않으며 앱 삭제·앱 데이터 초기화 시 복구할 수 없어요.’를 안내한다. 게스트 이용에 가입을 강요하지 않는다.
2. **회원가입:** 이메일·비밀번호·비밀번호 확인, 필요한 약관/개인정보 고지, 이메일 확인을 처리한다. 선택적 마케팅 동의는 기본 체크하지 않는다. 이메일 미확인 계정은 개인 로컬 이용을 계속할 수 있고 상대 연결/공유 요청은 차단한다.
3. **로그인:** 성공한 서비스 UID로 로컬 계정 영역을 연다. 비밀번호 오류·취소·연결 실패 때 기존 로컬 기록·이용 모드를 파괴하거나 다른 계정으로 바꾸지 않는다. 가입 여부를 알아낼 수 있는 상세 오류 대신 공통 안내를 사용한다.
4. **비밀번호 재설정:** 이메일로 공식 재설정 절차를 제공하고 가입 여부를 노출하지 않는 응답을 사용한다. 이메일 재설정 성공을 삭제된 개인 기록 복구로 설명하지 않는다.
5. **비로그인→로그인:** 기존 게스트 기록은 자동 업로드/공유하지 않는다. ‘기존 기록을 이 계정의 기기 내 개인 기록으로 옮기기/게스트 영역에 두기’를 선택하는 안을 권장한다. 옮기기는 같은 기기의 로컬 소유 영역 이동이다. 취소/실패 시 원본을 유지하고 중복의 덮어쓰기를 피한다.
6. **상대 계정 연결:** 비로그인/미확인 이메일에는 로그인/이메일 확인 안내. 확인 뒤에도 코드를 서버에서 재검증하고 상대·공유 범위를 확인한 후 연결한다. 로그인 성공만으로 초대를 자동 수락하거나 개인 기록을 복제하지 않는다.
7. **로그아웃·계정 전환:** 현재 계정의 서버 권한·공유 캐시를 닫고 게스트 영역으로 이동한다. 계정 A의 로컬 기록을 게스트나 B에게 노출하지 않는다. A의 기기 내 기록을 보관할지는 안내하고 기본 보관하는 안을 권장한다. 같은 설치에서 A로 다시 로그인한 경우의 열람은 앱 삭제 후 복구가 아니다.
8. **재설치:** 개인 맵/처리함/휴지통은 0건으로 시작한다. 계정 자체와 유효 연결 상태를 재인증할 수 있어도 개인 원본을 서버/파일/OS 백업에서 가져오지 않는다. 업데이트/일반 재실행은 기존 기록을 보존한다.
9. **회원탈퇴:** 재인증·계정 및 연결/공유 데이터 처리 안내·서버 삭제 요청과 현재 기기의 해당 계정 로컬 기록 정리를 제공한다. 오프라인 다른 기기의 즉시 삭제를 보장하지 않는다. 다른 기기의 토큰/서버 권한 회수와 다음 인증 확인 때의 정리도 설계한다.

## 5. 상태와 권한

상태는 `GUEST`, `EMAIL_UNVERIFIED`, `AUTHENTICATED`, `SESSION_RECHECK_REQUIRED`, `SIGNING_OUT`, `DELETION_PENDING`으로 구분하는 설계다. 이메일 확인과 세션 갱신은 SDK에 보이는 이전 값만 믿지 않고 연결 요청 시 서버에서 확인한다.

- 개인 로컬 저장/열람은 네트워크 장애와 독립한다. 이전 로그인 설치의 인증 재확인 대기 중에는 이미 식별된 본인 로컬 영역만 사용하고 새 연결/공유 서버 동작은 차단한다.
- 비로그인에서 클라이언트 버튼을 숨기는 것만으로 끝내지 않는다. 서버도 미인증 요청을 거절하고, 본인 UID·이메일 확인·계정 상태·초대/참여권을 검증한다.
- 상대 개인 맵은 로그인 여부와 무관하게 읽을 수 없다. 복제/저장 직전 권한 재확인, 코드 만료/재발급 무효화·단일 사용·최대 2인·동시 연결 제약을 서버 트랜잭션으로 처리한다.
- 게스트 상태의 미완료 공유 요청을 서버로 익명 전송하거나 로그인 후 자동 실행하지 않는다. 재로그인 후 확인 단계에서 다시 선택한다.
- 외부 공유 수신·편집·대기 저장에는 시작 시점의 소유 영역을 고정한다. 로그인/로그아웃/계정 전환 중 늦게 완료된 작업이 새 UID의 기록으로 들어가지 않게 하며 미저장 편집의 전환/취소를 안내한다.

## 6. 현재 구현과 충돌·개발 영향

| 현재 코드/문서 | 필요한 변경 | 현재 상태 |
|---|---|---|
| `GajahamApp.kt`의 JSON 백업/가져오기 버튼·파일 선택 callback과 `PlacesViewModel.kt`의 파일 처리 | 출시 UI·라우트·파일 callback 및 외부 파일로 개인 원본을 복구하는 경로 제거. 내부 Room 직렬화/검증과 사용자용 복구 기능은 구분 | 이번 분석에서는 미변경 |
| `Place`·Room v2에 사용자/영역 구분 없음, 출처 키 전역 UNIQUE | 게스트/계정 UID별 로컬 영역·출처 중복 범위 설계와 비파괴 DB 마이그레이션. 공유 캐시는 개인 원본과 분리 | 미구현 |
| `allowBackup=false`·백업/전송 제외 XML | 정책 유지·필요한 보완과 Galaxy 클라우드 복원/Smart Switch 실검증. 재설치와 업데이트를 구분해 기록 유실 방지 | 설정 구현, 기기 검증 미실행 |
| 기본 로그인·서버 없음 | 이메일 가입/확인/로그인/재설정/탈퇴, 실제 인증 제공자·서버 인가·운영 설정 | 미구현 |
| 개인 기록 클라우드 이전/복구를 2차에 제안한 이전 출시 문서 | 개인 원본 서버 이전/복구는 제외. 2차 명칭은 소셜 간편 로그인 추가로 정정 | 요구 문서 갱신 |
| 백업 가능성을 근거로 한 2MiB/5,000건 제한 | 새 로컬 용량·성능 정책을 구현 브리프에서 재검토. 근거 없이 저장 상한을 자동 확대하지 않음 | 분석 항목 |

기존 개발 버전에서 내보낸 외부 JSON·다른 사람이 보관한 공유 사본은 앱 삭제로 회수되지 않는다. 새 출시 앱은 JSON 가져오기/백업을 제공하지 않는 방향이며, 기존 설치 업데이트에서 사용자 기록을 일괄 삭제하는 조치로 대신하지 않는다.

## 7. 기술·서버 계약의 방향

Kotlin·Compose·Room은 유지한다. 기본 인증은 자체 비밀번호 서버를 새로 운영하기보다 **Firebase Authentication 이메일/비밀번호를 우선 검증하는 기술 제안**이다. 운영 프로젝트·리전·이메일 발송·사용량/비용·보안 설정을 확인한 뒤 구현 브리프에 SDK 버전과 실제 검사 명령을 고정한다. 계정 연결/공유 저장소·서버 런타임은 이번 분석으로 최종 선정하거나 배포하지 않았다. [이메일 인증 공식 구현](https://firebase.google.com/docs/auth/android/password-auth)

서버의 연결/공유 요청은 검증한 인증 토큰의 UID를 사용한다. 클라이언트가 보낸 이메일/UID/로그인 여부를 권한 증명으로 받아들이지 않는다. 만료·탈퇴/비활성화·중요 작업 재인증/토큰 회수 정책도 확인한다. 기본 ID 토큰 검증만으로 회수까지 확인했다고 표시하지 않는다. [토큰 검증과 회수 구분](https://firebase.google.com/docs/auth/admin/verify-id-tokens)

2차 소셜은 내부 UID와 로그인 수단을 분리해 설계한다. 이메일이 같다는 이유만으로 계정을 합치지 않고 기존 계정과 새 제공자 양쪽의 인증 및 사용자 확인을 거친다. Google은 공식 제공자 연결 경로를 검증한다. Kakao는 같은 인증 시스템과 연계할 서버 검증/매핑이 별도로 필요하며, 기본 Firebase 제공자 버튼 하나로 완료된다고 가정하지 않는다. [제공자 연결](https://firebase.google.com/docs/auth/android/account-linking), [맞춤 인증 토큰](https://firebase.google.com/docs/auth/admin/create-custom-tokens), [Kakao 공식 인증 API](https://developers.kakao.com/docs/ko/kakaologin/rest-api)

Android는 자동 백업/기기 이전이 제조사에 따라 달라질 수 있다. 현재 XML만으로 개인 기록의 재설치 복원 차단을 검증했다고 표시하지 않는다. 실제 Galaxy에서 삭제/재설치와 기기 이전을 검사해야 한다. [Android 백업·전송 정책](https://developer.android.com/identity/data/autobackup)

계정 생성 기능이 생기므로 앱 안과 외부 웹의 계정 삭제 요청 경로가 출시 조건에 추가된다. 개인 장소의 서버 백업이 없다는 이유로 인증 계정·이메일·연결/공유 데이터 삭제를 생략하지 않는다. [Play 계정 삭제 요건](https://support.google.com/googleplay/android-developer/answer/13327111?hl=en)

## 8. 단계별 개발안과 다음 산출물

**1차 기본 인증 개발:** 로컬 영역 분리·기존 DB 이전·사용자용 백업/가져오기 제외·손실 안내 → 이메일 가입/확인/로그인/재설정·세션/로그아웃·탈퇴 → 게스트 연결 차단과 서버 권한 검사. 상대 연결/공유를 실제 제공할 구현 증분은 해당 서버·공유 정책을 포함해 별도로 완료 판정한다. 로그인 화면 완성을 계정 연결·공유 맵 구현 완료로 확대하지 않는다.

**2차 사용자 확정 범위:** Google·Kakao 등의 간편 로그인과 기존 이메일 계정에 로그인 수단 연결/해제. 개인 원본의 로컬 보관·재설치 복구 불가 규칙은 유지한다. Instagram DM 수신은 소셜 로그인 추가와 별도 검증 대상이다.

다음 구현 브리프는 인증 프로젝트/환경, 로컬 소유 영역 마이그레이션, 개인정보/탈퇴/공유 보존 계약, 실제 제공할 서버 엔드포인트·SDK 버전·검증 명령을 정한다. 화면/도메인/서버 에뮬레이터 검사와 실제 메일 수신·인증/계정 삭제·Galaxy 검사를 분리한다. 구현 완료 판정은 실제 증거가 생긴 뒤 한다.
