## 목표·범위

로그인 개인 원본을 서버에 보관하고 같은 계정으로 지원 기기/브라우저에서 조회하는 것을 최신 기준으로 확정한다. 기존 로컬 전용 금지를 대체하고 게스트/계정·공유 사본·삭제/캐시·게스트 이동·저장 확인·동시 수정 경계를 문서화한다. AGENTS·기획·계약·잔여 작업을 일치시키며 Android/조사 실행 기록은 이력으로 보존한다.

이번은 사용자의 저장 정책 선택을 구현 전 기준에 반영하는 작업이다. 실제 웹앱/Firestore·운영 인증·계정 개설·유료 활성화·도메인 구매·배포·push/PR, Android 원본 자동 업로드·사용자용 JSON 백업/가져오기는 수행하지 않는다. 기존 `web/`는 패키지를 추가하지 않는 목업이며 `.claude/launch.json` 등 사용자 파일을 보존한다.

## 후속 구현·완료 기준

1. WEB-01에서 실제 웹 경로·스택/버전·검사 명령, Firebase Auth/Firestore Rules·계정 기록/인덱스, 서버 탈퇴 실행/재시도·리전/예산을 고정한다. 로그인+서버 개인 저장을 한 흐름으로 구현하고 게스트 IndexedDB·명시적 계정 저장을 분리한다.
2. 서버 확인 후 저장 완료·UID 직접 API 인가·두 브라우저 로그인/조회·사이트 데이터 삭제 후 재조회·동시 편집/계정 전환·탈퇴 경합을 실제 Emulator/웹 화면으로 검증한다. 기존 목업/Android 검사로 대신하지 않는다.
3. 지도·두 사람 공유는 이 원본 모델 위에 구현한다. 운영 프로젝트·메일·고지·실기기·배포는 별도 완료 조건이다. 본 브리프 DONE은 정책 문서 완료만 뜻한다.

설치 없는 URL 접속·이메일/게스트·2차 소셜·선택 공유·맵별 독립·Galaxy 브라우저 우선·최소 비용은 유지한다. 로그인 기록을 브라우저에만 둬 기기/사이트 데이터 변경으로 잃는 설계는 새 요구를 충족하지 않는다.
