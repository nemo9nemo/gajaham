# FIX-WEB-01 · 생성 재시도로 영구 삭제 취소 방지

- 상태: 구현·로컬 검증·독립 구현 리뷰 완료 · 고정 SHA 판정은 장부 참조

- 이전 구현 리뷰 주기: 3라운드 뒤 중복 요청 재시도 변형 P2가 남아 별도 수정 주기로 분리한다. 기능 범위를 확대하지 않는다.

## 범위·설계

원생성 R뿐 아니라 중복 반환된 별도 요청 Q도 처리 결과를 최소 영수증으로 고정한다. Q의 중복 응답이 유실된 후 R이 영구 삭제돼도 같은 Q가 새 원본을 만들면 안 된다. 서버와 게스트에서 원문 없는 `{duplicateOf: R}`/삭제 표식을 별도로 유지한다. 같은 Q 재시도는 R이 남아 있고 정규화한 원본 URL이 같을 때 중복을 반환한다. R이 삭제됐거나 URL을 바꿨으면 오류를 표시하고 입력을 유지한다. 요청 UUID를 새로 만든 명시적인 신규 저장은 별개다.

계정/게스트의 처리된 생성 요청은10만개 한도로 최소 메타 비용을 제한한다. 최초 생성과 최초 중복 처리만 소모하고 이미 처리된 요청 재시도는 소모하지 않는다. 서버의 원본 생성 횟수 createdCount와 처리 요청 횟수 operationCount를 구분한다. 원문 보관5000건/2MiB는 별도다. 계정 탈퇴·사이트 데이터 삭제 때 최소 영수증도 정리한다. UI/계약·보존 정책·WEB-01 검증/현황을 함께 맞춘다. 운영·배포·새 제품 기능은 추가하지 않는다.

## 검증

Node22·공식 demo Auth/Firestore/Functions suite에서 `node app-web/scripts/check.mjs --reuse-emulators`. 원생성/중복 응답 유실→타 기기 영구삭제→옛 요청 재시도, 기존 IDB v1 데이터 보존, 중복·재시도 카운터, 생성요청 상한, 탈퇴 영수증 정리, production 분리·헤더를 확인한다. 의존성 변경 없음. 별도 독립 읽기 전용 구현 리뷰 후 로컬 커밋, 새 SHA의 별도 worktree main 대비 리뷰를 받는다.
