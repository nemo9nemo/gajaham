## 실행 결과

- `npm --prefix app-web audit`·`npm --prefix worker audit`: 각각 취약점0. JSON: `tmp/codex/WEB-06-audit-web.json`·`tmp/codex/WEB-06-audit-worker.json`.
- 이동: 순수 함수의 150건/원인별429/연속503/UID 변경 검사와, 합성 API 응답의 Chromium 150건 중단·재개·중복 유지/동일 요청 재시도를 확인했다. 실제 로컬 API로 503 후 재접속·명시 재개/원본 정리와 기존 부분 실패/응답 유실/삭제 후 재생성 차단 회귀도 통과했다. 운영 Free의 150건 처리량/CPU는 측정하지 않았다.
- 편집: 독립 Chromium2개가 같은 실제 로컬 D1 기록을 수정해 충돌 비교·선택한 메모만 반영·나머지 최신 이름 유지, 닫기 경고 취소·페이지 이탈 경고 핸들러, 같은 프로필의 다른 탭에서 계정 변경 후 초안 제거를 확인했다. 게스트 중복의 휴지통 복원/명시 메모 저장과 대상 삭제 중 재조회도 통과했다.
- 모바일: 360×740·390×844·412×915·740×360·390×320, 24px 폼 글자/28px 제목의 합성 확대에서 가로 넘침·저장 버튼 접근·44px 닫기·제목 이름·포커스 복귀를 검사했다. 생성된 `tmp/codex/WEB-06-list-mobile.png`·`WEB-06-dialog-mobile.png`를 시각 확인했다. 실제 OS 글자 확대/키보드/TalkBack·Galaxy 뒤로가기 검사가 아니다.
- 메일: 공식 Auth Emulator에서 한국어 locale·60초 대기·재발송, 가입/미가입 동일 재설정 안내를 확인했다. 합성 설정 오류를 성공으로 삼키지 않는 것도 확인했다. 실제 메일함/링크·운영 열거 보호의 재검사는 아니다.
- 목록: 실제 로컬 D1 201건의200+1 페이지·UID 커서 무결성과 기존 오래된 목록 응답 차단 통과. 합성 API 0/200/201/2500건에서 전체 검색/건수·최근 수정순·최초 DOM50/더 보기를 검사했다. 서버 내부 필드를 포함한 직렬화 크기는 0/110870/111426/1769170bytes, 목록 호출1/2/2/13회, 첫 표시206/205/194/196ms였다. 한 번의 로컬 클라이언트 측정이며 운영 네트워크/DB 비용/성능 보장이 아니다. - 독립 리뷰 r2에서 복원 성공 뒤 목록 실패 시 중복 초안 폐기1건을 확인해 수정했다. 커밋 응답으로 비교 창을 유지하고, 조회503 상태에서도 초안/닫기 확인·선택 메모 저장을 검증해 최종46개가 통과했다. 명시 버리기는 폼 메모를 기존 값으로 복원하며 새 메모를 선택한 뒤 버리는 회귀도 확인했다.
- 커밋 SHA 리뷰 r1에서 DOMException 시간 초과의 연속 실패 분류와 이메일 확인 후 busy 중 화면 갱신 회귀2건을 확인해 수정했다. AbortError/TimeoutError/NetworkError는 연속2회에 중단하며 오류 중단 뒤 추가 목록 호출을 하지 않는다. 브라우저의 실제45초 AbortController 타이머를 가상 시계로2회 진행해 create2회·list0회·원본3개 유지·연결 경고를 확인했다. Emulator에서 emailVerified를 바꾼 뒤 '확인했어요'를 눌러 완료 패널/재발송 영역 제거도 확인했다. 전체48개를 재실행해 통과했다.
