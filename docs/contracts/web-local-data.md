# 웹 게스트 로컬 기록과 로그인 계정 캐시의 경계

기준: 2026-11-03 [결정 0008](../decisions/0008-account-cloud-records.md). **구현 전 계약**이다. 결정0007의 로그인 계정 원본 로컬 전용은 대체됐다. 계정 서버 원본·여러 기기 조회는 [계정 계약](web-account-data.md)을 따른다.

## 게스트 원본

- 로그인 없는 개인 이용은 유지한다. 장소·출처·메모·방문·처리함·휴지통은 현재 브라우저/프로필/origin의 IndexedDB guest 영역에 보관한다. 서버 계정을 만들거나 상대 연결/공유에 참여하지 않는다.
- 안내: “로그인하지 않은 기록은 이 브라우저에만 저장됩니다. 사이트 데이터를 지우거나 다른 브라우저·기기로 이동하면 이어서 볼 수 없습니다. 계정에 저장한 기록은 로그인 후 다른 기기에서도 볼 수 있습니다.”
- 배포·스키마/서비스 워커 갱신으로 기존 DB를 초기화하지 않는다. 용량/권한·DB 열기/이전 실패와 성공을 구분하고 로컬 트랜잭션 커밋 후 저장 완료를 표시한다.
- 로그인만으로 기존 게스트 원본을 자동 업로드하지 않는다. 대상/전송 항목 확인 후 사용자 선택으로 [계정 저장 절차](web-account-data.md)의 UID 고정·중복/부분 실패·서버 확인 후 이동 정리를 적용한다.
- 다른 origin/브라우저 게스트와 과거 Android Room 원본을 자동 이전하지 않는다. 사용자용 파일 내보내기/가져오기도 추가하지 않는다.

## 계정 캐시·탭·주소

- 로그인 계정의 원본은 서버다. 초기 캐시는 메모리 중심이며 영속 캐시/오프라인 큐는 별도 구현/검증 전 활성화하지 않는다. 사이트 데이터를 지웠다고 서버 원본까지 삭제된 것으로 안내하지 않는다.
- 읽기/쓰기·구독·폼·작업은 시작한 UID/guest와 세대에 고정한다. 로그아웃/전환 시 이전 구독/캐시를 닫고 다른 탭/늦은 응답이 새 계정/게스트에 노출되거나 저장되지 않게 한다.
- web.app/firebaseapp.com·개발/preview·자체 도메인은 origin이 다르다. 정식 주소는 하나로 고정한다. 같은 운영 프로젝트/UID·허용 주소의 계정은 서버 원본을 다시 읽지만 게스트 원본은 따라오지 않는다.
- PWA 아이콘 추가는 선택이며 URL 접속/계정 조회의 조건이 아니다. 아이콘 제거와 사이트 데이터 삭제는 다르다. navigator.storage.persist()도 게스트 영구 보존을 보장하지 않는다. [MDN 저장 수명](https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria)

## 입력·보안·공유

- 붙여넣기/직접 입력을 기본으로 한다. PWA 공유 수신은 지원 환경에서 추가 검증하며 모든 브라우저/Instagram 인앱의 대상 등록을 약속하지 않는다. [Chrome 공유 대상](https://developer.chrome.com/docs/capabilities/web-apis/web-share-target)
- 계정 저장은 서버 확인 기준이다. 통신 실패/미전송 입력은 기기 간 반영 완료와 구분한다. 게스트 로컬 저장과 계정 서버 저장의 실패 안내를 혼동하지 않는다.
- 서비스 워커 앱 셸 캐시에 인증/개인·공유 응답·토큰·비밀번호를 넣지 않는다. 비밀번호는 브라우저 저장소·로그에 직접 기록하지 않고 공식 SDK 세션과 구분한다.
- 입력 안전 렌더·HTTPS·CSP·의존성/키 제한을 검증한다. 관리자/비밀 키는 클라이언트에 넣지 않는다. 개인 기록·출처·메모를 광고/진단 이벤트·접근 로그로 유출하지 않는다.
- 개인 서버 원본은 본인만 보고 공유는 선택한 별도 사본만 담는다. 타인 개인 맵은 조회/복제 목록에 보이지 않는다. 같은 계정 기기 간 갱신과 서로 다른 맵의 편집/삭제 독립은 별개다.

실제 동작은 [AUTH-03 검증](../validation/AUTH-03-account-cloud-policy.md)에서 확인한다. 과거 Android/목업 실행 증거로 대신하지 않는다.
