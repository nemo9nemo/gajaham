# 이메일 로그인·비로그인 개인 이용 계약

**2026-11-03 최신 저장 요구:** [결정 0008](../decisions/0008-account-cloud-records.md)에 따라 로그인 개인 원본을 서버에 보관하고 같은 계정으로 다른 기기/브라우저에서 조회한다. 게스트만 로컬 전용이며 기존 Android/Room 구현은 이력이다. [계정 계약](web-account-data.md)·[게스트/캐시 계약](web-local-data.md)을 따르고 실제 서버 기능/운영 완료와 구분한다.

기준: 2026-10-26 [결정 0005](../decisions/0005-login-and-device-local-records.md). 분석/설계 계약이다. 2026-10-27 이메일 SDK·로컬 영역·파일 백업 제거·외부 탈퇴 페이지 구현은 [AUTH-02](../plans/AUTH-02-email-local-mode.md), [결정 0006](../decisions/0006-email-auth-local-scopes.md)과 [실행 증거](../validation/AUTH-02-email-local-mode.md)를 따른다. 이 문서의 논리적 공유 서버 API는 아직 실제 API가 아니다. [기능 분석](../plans/AUTH-01-login-guest-analysis.md), [전체 검증 시나리오](../validation/AUTH-01-login-guest.md)를 함께 본다.

## 확정 요구

이메일+비밀번호 기본 로그인, 2차 카카오/구글 간편 로그인. 게스트는 브라우저 로컬 개인 기능을 사용하고 상대 연결/공유에 참여하지 못한다. 로그인 계정의 개인 원본은 서버에 보관하며 네트워크가 가능한 지원 브라우저에서 같은 유효 계정으로 재조회/변경 반영한다. 사이트 데이터 삭제/기기 변경으로 서버 원본을 잃지 않도록 구현한다. 설치는 전제 조건이 아니다.

## 식별자와 저장 경계 제안

| 개념 | 식별·보관 | 금지/분리 |
|---|---|---|
| 게스트 영역 | 현재 브라우저/프로필/origin의 IndexedDB. 서버 계정 없음 | 사용자 선택 전 업로드·공유 참여 금지 |
| 계정 | 인증 제공자가 검증한 안정적 서비스 UID | 클라이언트의 이메일/UID 문자열만으로 신원 인정 금지 |
| 계정 개인 원본 | 서버의 검증된 UID 영역 + 개인 기록 ID | 다른 UID 열람/수정·소유자 변조 금지. 사용자 파일 복구 UI는 없음 |
| 로그인 수단 | `(provider, verified provider subject)` → 서비스 UID | 이메일 일치만으로 자동 병합 금지, 한 제공자 식별자의 중복 소유 금지 |
| 연결/공유 데이터 | 검증된 사용자·활성 참여권·공유 맵별 서버 기록 | 참여자의 개인 DB 전체를 연결/복구 데이터로 업로드 금지 |

실제 서버 문서/인덱스·요청 ID·검사 명령은 WEB-01에서 고정한다. 중복 키는 UID별로 격리하고 서버 커밋을 확인한다. 과거 Room v2→v3의 guest 이전은 AUTH-02의 Android 검사 이력이며 서버 업로드/웹 이식 증거가 아니다.

## 권한 행렬

| 요청 | 게스트 | 이메일 미확인 | 인증/이메일 확인 완료 | 재확인 필요·탈퇴 중 |
|---|---|---|---|---|
| 게스트 개인 로컬 저장/열람 | 허용 | 게스트 전환 후 허용 | 게스트 전환 후 허용 | 계정 기록을 게스트에 노출하지 않음 |
| 본인 계정 서버 원본 저장/열람 | 거절 | 정상 인증/계정 상태·UID 인가 후 허용 | 정상 인증/계정 상태·UID 인가 후 허용 | 정지/탈퇴 pending은 새 서버 접근 거절, 삭제 재시도는 별도 인가 경로 |
| 초대 코드 발급·재발급·취소 | 거절 | 거절 | 활성 계정·연결 상태 확인 후 허용 | 거절 |
| 코드로 상대/연결 대상 확인 | 거절 | 거절 | 코드 유효성·접근 범위 확인 후 제한적으로 반환 | 거절 |
| 연결 수락·공유 읽기/쓰기/복제 | 거절 | 거절 | 매 요청 서버 인가, 권한 종료/경합 시 거절 | 거절 |
| 다른 사용자의 개인 맵 열람 | 거절 | 거절 | 거절 | 거절 |

비밀번호 재설정/확인 메일은 인증 서비스의 남용 방지·호출 제한을 적용한다. 상대 연결은 이메일 확인 상태를 서버가 검증한다. 연결 요청 실패를 성공으로 안내하거나 로컬 `loggedIn=true`로 통과시키지 않는다.

## 요청·응답의 논리 계약

아래는 엔드포인트 이름의 확정이 아닌 필요한 기능의 계약이다.

- 가입/로그인/재설정: 공식 인증 SDK·검증된 메일 경로 사용. 로그인/재설정 응답으로 특정 이메일의 가입 여부를 공개하지 않는다. 앱/문서/로그에 비밀번호·토큰을 출력하지 않는다.
- 연결 코드 발급/회수: 서버가 UID·이메일 확인·계정 상태·기존 활성 연결을 검사한다. 코드 상태 `active/expired/cancelled/used`, 만료 시각·재발급 무효화·속도 제한·중복 요청 처리가 필요하다.
- 연결 확인/수락: 로그인 후 코드를 재검증한다. 대상 확인과 사용자의 명시적 수락을 거친 뒤 단일 사용/최대 2인/활성 연결 제약을 트랜잭션에서 보장한다. 코드를 입력했거나 로그인됐다는 이유만으로 개인 기록을 공개하지 않는다.
- 공유 저장/복제: 실행 직전 참여권을 확인한다. 개인→공유는 선택 필드만 별도 사본, 공유→내 개인은 현재 계정의 서버 개인 맵에 새 기록으로 저장한다. 원본 유지·맵별 독립 편집은 유지하며 게스트 공유 접근은 차단한다.
- 탈퇴: 최근 인증 확인→삭제 요청 식별자/상태 제공→인증·계정/연결·공유 정책에 따른 삭제/비식별 처리. 현재 기기의 해당 계정 개인 영역 정리, 서버 권한/토큰 회수와 재시도 처리가 필요하다. 공유/보존 정책 미결 항목은 구현 브리프에서 명시한다.
- 계정 개인 기록: 검증된 UID의 서버 원본을 저장/조회/수정/삭제하고 같은 계정으로 다른 기기에서 다시 읽는다. 저장 실패/충돌·운영 백업/보존은 별도 처리하며 사용자용 파일 내보내기/가져오기는 제공하지 않는다.

## 모드 전환·생명주기

- 게스트→로그인: 계정 서버 원본을 조회한다. 게스트는 대상/전송 항목 확인 후 사용자 선택으로 계정에 저장하며 중복은 덮어쓰지 않는다. 서버 확인 전 로컬 원본 삭제 금지·요청 ID로 재시도 중복 방지·부분 성공/정리 실패를 안내한다.
- 로그아웃: 게스트로 전환하고 계정/공유 구독·캐시·작업 접근을 닫는다. 서버 원본은 유지하며 다른 기기에서도 동일 UID 정상 로그인으로 조회한다.
- 공유 수신·미저장 폼·가져온 후보·대기 저장 작업에는 시작 시점의 로컬 소유 영역을 고정한다. 계정/모드 전환 뒤 현재 UID를 다시 읽어 다른 영역에 저장하지 않는다. 편집 폐기/전환 확인을 거치고 진행 중 처리의 보존·취소 결과를 안내한다.
- 웹 배포/재접속·사이트 데이터 삭제/기기 변경: 계정 서버 원본은 유지/재조회한다. 게스트 로컬 원본과 미전송 입력은 이 보장에 포함하지 않는다. 영구 삭제/탈퇴 원본의 복구 약속이 아니다.
- 계정 삭제: 지속되는 서버 삭제 요청·접근 정지·개인 원본/하위 데이터/작업·인증 정리 결과와 재시도를 관리한다. 다른 오프라인 기기의 즉시 캐시 삭제는 보장하지 않는다. 같은 이메일 신규 가입의 새 UID에 과거 원본을 자동 연결하지 않는다.
- 이미 사용자가 내보낸 과거 개발 버전의 외부 파일/공유 사본은 회수할 수 없다. 출시 앱의 JSON 백업/가져오기를 제거하는 정책을 적용하되 기존 설치의 정상 데이터를 일괄 초기화하지 않는다.

## 구현 전 확정할 기술 항목

인증 프로젝트·개인/공유 서버 문서와 Rules/인덱스·리전/보존, 메일/허용 주소·남용 방지, 토큰 검증/최근 인증·탈퇴 pending/정리 실행 환경, 중복/동시 편집·게스트 계정 저장, 공유 종료/탈퇴·잔여 참여자 범위, 계정 삭제 페이지의 서버 정리 연동, 실제 SDK/지도/광고 데이터 흐름·고지/비용을 구현 브리프에서 고정한다. 기능 요구 확정과 구현/검증을 구분한다.
