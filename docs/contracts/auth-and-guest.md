# 이메일 로그인·비로그인 개인 이용 계약

기준: 2026-10-26 [결정 0005](../decisions/0005-login-and-device-local-records.md). 분석/설계 계약이다. 2026-10-27 이메일 SDK·로컬 영역·파일 백업 제거·외부 탈퇴 페이지 구현은 [AUTH-02](../plans/AUTH-02-email-local-mode.md), [결정 0006](../decisions/0006-email-auth-local-scopes.md)과 [실행 증거](../validation/AUTH-02-email-local-mode.md)를 따른다. 이 문서의 논리적 공유 서버 API는 아직 실제 API가 아니다. [기능 분석](../plans/AUTH-01-login-guest-analysis.md), [전체 검증 시나리오](../validation/AUTH-01-login-guest.md)를 함께 본다.

## 확정 요구

이메일+비밀번호 기본 로그인, 2차 카카오/구글 간편 로그인. 게스트는 개인 로컬 기능을 사용하고 상대 계정 연결/공유 맵에 참여할 수 없다. 개인 원본은 로그인 여부와 무관하게 기기에만 보관하며 앱 삭제/데이터 초기화 후 앱에서 복구하지 않는다.

## 식별자와 저장 경계 제안

| 개념 | 식별·보관 | 금지/분리 |
|---|---|---|
| 게스트 영역 | 해당 설치의 로컬 영역. 서비스 계정 생성 없음 | 익명 서버 계정·공유 참여자 ID로 대체하지 않음 |
| 계정 | 인증 제공자가 검증한 안정적 서비스 UID | 클라이언트의 이메일/UID 문자열만으로 신원 인정 금지 |
| 개인 로컬 기록 | 설치 + `guest` 또는 `account:<uid>` 소유 영역, 로컬 장소 ID | 계정 간 열람·개인 원본 서버 컬렉션/API·복구 파일 경로 없음 |
| 로그인 수단 | `(provider, verified provider subject)` → 서비스 UID | 이메일 일치만으로 자동 병합 금지, 한 제공자 식별자의 중복 소유 금지 |
| 연결/공유 데이터 | 검증된 사용자·활성 참여권·공유 맵별 서버 기록 | 참여자의 개인 DB 전체를 연결/복구 데이터로 업로드 금지 |

실제 컬럼/별도 DB 파일 선택은 구현 브리프에서 고정한다. 기존 Room v2의 모든 기록을 기존 설치 게스트 영역으로 보존하는 비파괴 이전이 필요하다. 출처 UNIQUE는 소유 영역을 포함하도록 재설계하고 현재 전역 UNIQUE를 그대로 계정 간 공유하지 않는다.

## 권한 행렬

| 요청 | 게스트 | 이메일 미확인 | 인증/이메일 확인 완료 | 재확인 필요·탈퇴 중 |
|---|---|---|---|---|
| 본인 로컬 개인 저장/열람 | 허용 | 허용 | 허용 | 기존 설치에서 식별된 본인 영역만, 계정 전환/삭제 상태에 맞춤 |
| 초대 코드 발급·재발급·취소 | 거절 | 거절 | 활성 계정·연결 상태 확인 후 허용 | 거절 |
| 코드로 상대/연결 대상 확인 | 거절 | 거절 | 코드 유효성·접근 범위 확인 후 제한적으로 반환 | 거절 |
| 연결 수락·공유 읽기/쓰기/복제 | 거절 | 거절 | 매 요청 서버 인가, 권한 종료/경합 시 거절 | 거절 |
| 다른 사용자의 개인 맵 열람 | 거절 | 거절 | 거절 | 거절 |

비밀번호 재설정/확인 메일은 인증 서비스의 남용 방지·호출 제한을 적용한다. 상대 연결은 이메일 확인 상태를 서버가 검증한다. 연결 요청 실패를 성공으로 안내하거나 로컬 `loggedIn=true`로 통과시키지 않는다.

## 요청·응답의 논리 계약

아래는 엔드포인트 이름의 확정이 아닌 필요한 기능의 계약이다.

- 가입/로그인/재설정: 공식 인증 SDK·검증된 메일 경로 사용. 로그인/재설정 응답으로 특정 이메일의 가입 여부를 공개하지 않는다. 앱/문서/로그에 비밀번호·토큰을 출력하지 않는다.
- 연결 코드 발급/회수: 서버가 UID·이메일 확인·계정 상태·기존 활성 연결을 검사한다. 코드 상태 `active/expired/cancelled/used`, 만료 시각·재발급 무효화·속도 제한·중복 요청 처리가 필요하다.
- 연결 확인/수락: 로그인 후 코드를 재검증한다. 대상 확인과 사용자의 명시적 수락을 거친 뒤 단일 사용/최대 2인/활성 연결 제약을 트랜잭션에서 보장한다. 코드를 입력했거나 로그인됐다는 이유만으로 개인 기록을 공개하지 않는다.
- 공유 저장/복제: 현재 참여권을 실행 직전에 확인한다. 개인→공유는 선택한 필드만 업로드, 공유→개인은 사용자가 선택한 새 로컬 기록으로 저장한다. 원본은 유지하고 이후 편집은 맵별로 독립한다.
- 탈퇴: 최근 인증 확인→삭제 요청 식별자/상태 제공→인증·계정/연결·공유 정책에 따른 삭제/비식별 처리. 현재 기기의 해당 계정 개인 영역 정리, 서버 권한/토큰 회수와 재시도 처리가 필요하다. 공유/보존 정책 미결 항목은 구현 브리프에서 명시한다.
- **개인 기록 백업·서버 복구 요청은 설계하지 않는다.** 로그인과 계정 복구는 기기에서 삭제된 장소 원본을 복구하는 API가 아니다.

## 로컬 모드 전환·생명주기 제안

- 게스트→로그인: 게스트 원본을 자동 업로드하지 않는다. 사용자 선택에 의한 기기 내 소유 영역 이동만 허용하고, 중복 처리·이동 전체를 트랜잭션으로 검증한다. 취소/실패 시 이전 기록 보존. 기존 계정 기록 덮어쓰기 금지.
- 로그아웃: 게스트 영역으로 전환하고 공유 캐시/현재 계정 접근을 닫는다. 계정 소유 로컬 원본을 게스트에 노출하지 않는다. 같은 설치에서 같은 UID로 재인증했을 때만 그 영역을 다시 연다.
- 공유 수신·미저장 폼·가져온 후보·대기 저장 작업에는 시작 시점의 로컬 소유 영역을 고정한다. 계정/모드 전환 뒤 현재 UID를 다시 읽어 다른 영역에 저장하지 않는다. 편집 폐기/전환 확인을 거치고 진행 중 처리의 보존·취소 결과를 안내한다.
- 앱 업데이트/프로세스 재시작: 데이터 유지. 앱 삭제/데이터 초기화: 개인 원본 소실, 로그인·간편 로그인·파일·OS 자동 복원으로 되살리는 기능 제공 안 함.
- 계정 삭제: 현재 기기 로컬 정리와 서버 계정 삭제를 구분해 완료 상태를 관리한다. 다른 오프라인 기기의 즉시 로컬 삭제는 보장하지 않는다. 삭제 후 같은 이메일 신규 가입은 새 UID이며 이전 로컬 영역을 자동 연결하지 않는다.
- 이미 사용자가 내보낸 과거 개발 버전의 외부 파일/공유 사본은 회수할 수 없다. 출시 앱의 JSON 백업/가져오기를 제거하는 정책을 적용하되 기존 설치의 정상 데이터를 일괄 초기화하지 않는다.

## 구현 전 확정할 기술 항목

인증 프로젝트·서버/공유 저장소·운영 리전과 보존, 메일 발송/재설정 도메인·남용 방지, 토큰 검증/회수·최근 인증 기준, 계정별 Room 이전·중복 처리, 공유 종료/탈퇴·잔여 참여자의 데이터 범위, 앱 내/외부 탈퇴 요청 경로, SDK·지도·광고의 실제 데이터 흐름과 고지. 기본/소셜 로그인에 대한 기능 요구는 확정됐고 이 기술 항목들은 구현·검증 대상으로 구분한다.
