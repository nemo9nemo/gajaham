# Android 개인 저장 데이터 계약 v1

**2026-11-03 범위 구분:** 이 계약은 기존 Android/Room 구현 이력이다. 새 웹앱의 로그인 개인 원본은 [결정 0008](../decisions/0008-account-cloud-records.md)·[계정 계약](web-account-data.md)에 따라 서버에 보관하고 여러 기기에서 조회한다. 기존 Android에 서버 업로드/동기화를 구현한 것은 아니며 이 문서의 로컬 전용을 최신 웹 정책으로 사용하지 않는다.

기준: 2026-10-20 / [APP-01](../plans/APP-01-android-local-core.md). 서비스 계정·서버·광고·분석 수집 없이 앱 전용 DB를 사용한다.

**후속 계약 2026-10-27:** 아래 v1/v2·JSON 백업 항목은 APP-01 당시 구현 이력이다. 현재 앱은 [AUTH-02](../plans/AUTH-02-email-local-mode.md)/[결정 0006](../decisions/0006-email-auth-local-scopes.md)의 Room v3 계약을 따른다. 기존 기록은 guest로 보존하고 `(ownerScope, canonicalSource)` UNIQUE·소유 영역 조건으로 접근을 분리한다. 선택/접근 정지/탈퇴 pending은 Room metadata에 둔다. 파일 백업/가져오기 UI·Repository·SAF 경로는 제거했다. 개인 원본은 로그인 후에도 로컬 전용·앱 삭제 후 복구 불가다. 최신 모드/이동/삭제 정책은 [로그인·비로그인 계약](auth-and-guest.md)과 AUTH-02를 우선한다.

## 요구와 정책

- 외부 `ACTION_SEND text/plain`과 앱 입력의 http/https 링크를 받는다. 문자 16,384개·한 번에 10개까지다. DB 트랜잭션 커밋 전에는 접수 완료로 알리지 않는다.
- 공유 완료 상태는 저장된 입력 지문과 함께 복원한다. 이전에 대기 중이던 공유의 완료가 새 공유를 완료로 바꾸지 않는다. 편집 중 새 공유는 저장하되 기존 편집 화면·입력을 유지한다.
- 원본 URL을 보존한다. 알려진 Instagram 게시물 경로의 호스트·트래킹 쿼리만 중복 판정에 정규화한다. 일반 URL의 쿼리·해시 경로·인코딩은 구분한다. URL 사용자 자격 증명·잘못된 형식은 거절한다.
- Instagram 특수 정규화는 포트 생략 또는 해당 scheme의 기본 포트(HTTP 80/HTTPS 443)에만 적용한다. 비기본 포트는 일반 URL 규칙으로 포트·쿼리·해시를 보존한다. 2026-10-26 [저장 정확성 지적 조치](../plans/FIX-LAUNCH-01-save-integrity.md)에서 회귀 검증한다.
- 같은 출처 재접수는 기존 편집을 보존하고 활성 상태를 유지한다. 보관 기간 내 휴지통 기록이면 내용 그대로 복원한다. 기간이 지난 출처를 다시 받으면 이전 기록을 복원하지 않고 새 접수로 만든다.
- 이름·주소를 사용자가 확인하기 전에는 처리함에 둔다. 외부 자료 확보·주소·메뉴 추출을 했다고 표시하지 않는다.
- 미확정 링크도 이름·주소를 채우지 않고 개별 휴지통 이동·복원할 수 있다. 편집 중 삭제하면 미저장 입력 폐기를 안내하고 원래 저장된 기록을 옮긴다.
- 저장 이유·메뉴·분류·방문 상태·수정·삭제는 이 기기에만 반영한다. 전체 초기화는 앱의 기록과 준비 중인 가져오기 자료를 비운다. 외부 파일은 별개다.

## 저장 설계

Room 스키마 2의 `places`: `id` UUID PK, `canonicalSource` nullable UNIQUE, `payload` JSON, `createdAt`, `trashedAt`. 테이블 형태는 스키마 1과 같다. 버전 1→2 데이터 마이그레이션에서 원본 payload의 출처로 중복 키를 재계산하며, 사용자 기록·시간은 보존한다. 출처 없는 직접 장소는 각각 별도 ID로 저장한다. 스키마 JSON을 체크인하고 파괴적 마이그레이션을 쓰지 않는다. JSON 백업 형식은 버전 1을 유지한다.

단일 트랜잭션에 접수·저장·재접수·가져오기를 묶는다. 수정은 현재 DB 기록을 기준으로 하며 과거 화면의 값으로 출처·방문 상태를 덮어쓰지 않는다. UNIQUE는 동시에 재접수해도 한 출처가 중복 생성되지 않도록 한다.

휴지통은 30일이 지난 항목을 앱 시작·저장소 정리에서 제거한다. 제조사 절전 상태에서 정확히 30일째 실행되는 백그라운드 정리는 이번 범위가 아니다.

## 백업 형식과 안전성

JSON 필수 헤더: `format="gajaham-local-backup"`, `version=1`, `exportedAt`, `records`. 기록의 ID·URL·문자 길이·시간·중복을 전체 검증한 뒤 적용한다. 잘못된 UTF-8·미지원 헤더·2MiB 초과·5,000건 초과 파일은 거절한다. 파일 읽기도 2MiB에서 제한한다.

현재 기록 우선 병합: 같은 ID 또는 정규 출처가 있으면 덮어쓰지 않고 건너뛴다. 오래된 휴지통 기록은 기존 DB와 백업 양쪽에서 중복 판정 전에 제외한다. 미리보기 이후 실행 시 DB 트랜잭션에서 현재 상태로 다시 판정한다. 중간 실패는 전체 롤백한다.

파일이 작아도 기존 데이터와 합쳐 용량을 넘을 수 있다. 저장·수정·가져오기 트랜잭션에서 전체 백업 크기를 확인하고 헤더 여유 1KiB를 남긴다. 실패하면 원본을 유지한다. 이 제한으로 저장은 됐으나 전체 백업은 못 하는 상태를 예방한다.

파일은 평문이며 메모·원본 URL·휴지통 기록을 포함한다. 사용자가 Android 파일 선택기로 저장소를 선택하며 외부 저장소의 보안·삭제는 그 제공자와 사용자에게도 달려 있다. 자동 백업·기기 이전 제외 XML과 `allowBackup=false`를 사용하고 OEM 실제 동작은 기기 검사 전 보장하지 않는다.

## 검증

도메인·URL·백업 오류는 core JVM, Room 보존·동시 접수·가져오기 롤백은 Robolectric, Android 공유 Intent·화면 동작은 Activity/Compose 로컬 검사로 확인한다. [검증 시나리오](../validation/APP-01-android-local-core.md)에 실제 결과와 기기 미실행을 기록한다.
