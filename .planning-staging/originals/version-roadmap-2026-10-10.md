# 가자함 (Gajaham) — 버전별 기능 확장안

작성일: 2026-10-10. 수정일: 2026-10-12. 서비스명은 **가자함**, 영문 표기는 **Gajaham**으로 확정했다. [시장조사](./market-research-2026-10-10.md)를 바탕으로 한 기획 제안이다. 개발 착수나 출시 일정 확정 문서가 아니다.

**통합 기획서 안내:** 출시 검토 기준은 [가자함 (Gajaham) 서비스 기획서](./product-plan-2026-10-11.md)에 정리했다. 해당 기획서에서는 반복 사용을 확인하기 위해 V1.0 기능 중 관심 표시·수동 후보 선택·최종 확정을 V0.5 베타로 앞당긴다. 조건별 자동 추천은 V1.0에 유지한다. V3.0은 운영 확장 단계이며, 외부 베타의 데이터 분리·공유 종료와 필요한 유료화 준비를 그때까지 미룬다는 뜻이 아니다. 구체적인 첫 베타 범위와 검증 기준은 통합 기획서를 우선한다.

**10월 11일 반영: 기본 수집 방식을 ‘서비스 계정에 DM으로 전달’로 변경한다.** 사용자가 인스타 게시물의 공유 버튼에서 서비스 계정을 선택하면 게시물을 수신하고, 결과는 답장과 모바일 웹 지도로 확인하도록 설계한다. 두 사람은 각각 서비스 계정에 최초 메시지를 보내 같은 비공개 공간에 연결한다. 이후 각자가 전달한 게시물이 같은 지도에 모인다. 링크 붙여넣기는 보조 입력으로 유지한다.

**확정 요구: 첫 출시는 인스타 DM으로 시작하고, 이후 블로그 링크 전달을 지원한다.** 블로그는 V0.8의 첫 콘텐츠 확장으로 배치한다. 목표 사용 흐름은 기존과 동일하게 서비스 계정의 DM에 블로그 URL을 보내고 같은 지도에서 결과를 확인하는 것이다. 인스타 공유 게시물과 메시지 본문의 외부 URL 수신을 각각 검증한다. 블로그 플랫폼별 분석 지원은 실제 글로 확인한 뒤 순차 공개한다.

**처음부터 ‘받는 경로’와 ‘읽는 콘텐츠’를 분리한다.** 받는 경로는 인스타 DM·웹 링크 입력·향후 앱 공유이고, 읽는 콘텐츠는 인스타 게시물·블로그 글·향후 다른 출처다. 수신한 링크에서 출처를 판별한 뒤 출처별 읽기 기능을 거치고, 장소·메뉴·요약 추출과 지도 저장은 공통 기능을 사용한다. 신규 블로그 지원을 위해 기존 지도·커플 공간을 다시 만들지 않도록 설계한다.

저장 정보에는 수신 경로, 콘텐츠 출처, 원본 URL, 보낸 사람, 공동 공간, 처리 상태를 구분해서 남긴다. 장소와 참고 게시물도 구분하여 같은 가게의 인스타 게시물과 블로그 글을 하나의 장소에 함께 연결한다. 메뉴·방문 팁은 각각 어느 글에서 나온 내용인지와 작성일·확인 시점을 가능한 범위에서 보존한다. 새 글을 추가해도 사용자가 수정한 정보와 기존 참고 글은 유지한다.

Meta 공식 문서는 프로 계정의 메시지 송수신과 공유 게시물 URL의 웹훅 수신을 안내한다. 수신 URL만으로 제3자 게시물의 본문·영상 접근까지 보장되지는 않으므로 콘텐츠 확보·자동 추출은 별도 검증한다. 서비스 계정은 비즈니스·크리에이터 계정으로 준비하고 권한·운영 범위에 따른 심사 요건·회신 규칙을 확인한다. 그룹 메시징은 공식 API 지원 대상이 아니므로 각 이용자가 서비스 계정에 개별 전달하는 구조로 검증한다. [Meta 공식 API 문서](https://www.postman.com/meta/instagram/documentation/6yqw8pt/instagram-api?entity=request-23987686-e2cfad80-45dd-4111-9ac4-9ae96b9d7ed0)

**권장 방향은 ‘기억하기 → 함께 고르기 → 계획하기 → 다음 만남에 활용하기’다.** 사용자가 공유한 게시물의 내용을 다시 이해하고, 두 사람이 방문할 곳을 결정하는 데 집중한다. 우선 국내 장소와 연인 두 명의 비공개 공간을 기준으로 한다. 다른 커플 대상 공개 서비스와 유료화는 뒤쪽의 선택 단계로 둔다.

**제품의 약속은 ‘둘이 가자고 했던 곳, 무엇이 좋았는지까지 기억해 주는 지도’로 제안한다.** 단순 지도 저장·공동 목록·메뉴 추출은 이미 경쟁 서비스에서 제공하므로, 확장의 판단 기준은 저장량뿐 아니라 다시 찾는 수고와 장소 결정에 걸리는 시간이다. 이 판단의 근거는 앞선 시장조사에 정리했다.

**V0에서는 실제 콘텐츠로 제품의 약속을 검증한다.** 본문에 정보가 있는 게시물 10개, 이미지·영상에만 정보가 있는 게시물 10개, 여러 장소·지점·행사가 섞인 게시물 10개를 선정한다. 가능한 입력 경로별로 저장 성공 여부, 장소 일치 여부, 추천 메뉴의 근거를 기록한다. 주소를 추측해서 지도에 확정하는 사례와 잘못된 메뉴를 생성하는 사례는 별도로 본다. 자료 확보가 안 되는 링크에는 캡처·본문·장소 검색으로 보완하는 경로를 둔다. 출처별 허용 접근 방식과 실제로 얻을 수 있는 데이터가 확인된 범위에서 자동 분석을 설계한다.

초기 실험에서는 ‘30개 중 24개 이상이 자동으로 유용한 장소 카드가 됨’을 임시 목표로 제안한다. 실패·미지원 링크도 30개에 포함한다. 이 값은 시장 평균이나 검증된 성능 기준이 아니다. 잘못된 지점·근거 없는 메뉴를 별도로 집계하고, 출시 전에는 더 다양한 표본으로 확인한다. 자동 완성률이 낮다면 기능을 늘리기 전에 지원 입력과 처리 방식을 조정한다.

**V0.1에서 원래 요청한 핵심 기능을 한 번에 경험하게 한다.**

- 서비스 계정으로 전달한 게시물이나 붙여넣은 링크를 먼저 보관한다. DM에는 허용된 회신 범위에서 접수와 결과 링크를 안내하고, 분석이 끝나면 장소 카드와 웹 지도를 갱신한다. 처리 중·보완 필요 상태를 보여준다.
- 확보 가능한 본문·이미지에서 장소명, 카테고리, 짧은 설명, 게시물 추천 메뉴를 추출한다. 없는 정보는 비워두고 모든 필드를 수정할 수 있게 한다.
- 원본 링크, 저장 시각, 저장한 사람을 함께 남긴다. 사용자가 수정한 정보가 이후 자동 갱신보다 우선한다.
- 맛집·카페·놀거리 필터, 장소명·지역 검색, 가고 싶은 곳·다녀온 곳 상태를 제공한다.
- 지점이 모호하면 장소 후보를 선택하게 한다. 위치 미확정 항목은 목록에 보관하고 장소가 정해지면 지도에 표시한다.
- 초대 링크로 두 사람이 같은 공간을 사용한다. 추가·수정·삭제와 초대 취소·공유 종료의 동작을 정한다.
- 지도 앱에서 길찾기를 열 수 있게 한다. 삭제 복구와 기본 데이터 내보내기도 초기 기록 보호 범위에 포함한다.

화면은 지도·목록, 장소 상세 카드, 링크 추가, 초대·설정으로 시작한다. 최초 DM에서 제공하는 연결 경로로 각자의 계정과 공동 공간을 확인하고, 이후에는 인스타에서 서비스 계정으로 전달해 저장한다. 결과 조회·수정은 모바일 웹에서 제공하는 안을 우선 검증한다. 모바일 앱과 OS 공유 메뉴 확장은 실제 사용 수요에 따라 추가한다.

V0.1에서는 인스타 콘텐츠 분석에 집중하되, 링크 수신과 출처 판별 구조는 블로그 추가를 수용하도록 만든다. 아직 지원하지 않는 출처를 받으면 분석 지원 여부를 안내하고 원본 링크를 보관한다. 접수 완료와 장소 분석 완료는 구분한다.

**V0.5는 스냅샷의 내용과 수집 편의성을 완성하는 단계다.**

대표 이미지 또는 사용자가 올린 캡처, 한 줄 소개, 추천 메뉴와 이유, 방문 팁, 원본 링크를 한 카드로 묶는다. 가격·영업시간 등 변할 수 있는 정보에는 출처와 확인 시점을 붙인다. 게시물의 주장과 사용자 메모, 방문 후 평가는 구분해서 표시한다. 자동 캡처·원본의 영구 보존은 별도의 콘텐츠 확보 검증이 필요하며, 원본 임베드만으로 삭제 후 보존을 보장하지 않는다.

이 단계에 한 게시물 속 여러 장소 분리, 같은 장소에 여러 게시물 연결, 중복 링크 처리, 이미지 OCR 보완, 저장 완료 알림과 재시도를 넣는다. 긴 영상의 전체 분석은 기존 처리로 놓치는 정보가 많을 때 추가한다. V0에서 검증한 개별 DM 전달을 기본 입력으로 유지하고, 모바일 앱의 OS 공유 메뉴 등 추가 입력 경로는 수요에 따라 확장한다.

예시 카드의 내용은 ‘성수 카페 / 피스타치오 라테 추천 / 테라스 분위기 / 주말 대기 언급 / 내가 남긴 “서울숲 갔다가” 메모’다. 이미지가 예쁘게 보이는 것과 방문 판단에 필요한 정보가 채워지는 것을 함께 평가한다.

**V0.8은 블로그 링크를 같은 저장 경험으로 연결한다.** 서비스 계정에 블로그 URL을 DM으로 보내거나 웹에 붙여넣으면 출처를 판별하고, 지원하는 사이트에서 확보 가능한 본문·이미지를 읽어 장소 카드에 정리한다. 네이버 블로그를 우선 검증 후보로 두고, 티스토리·일반 블로그는 실제 사용 비중과 처리 결과에 따라 추가한다. 특정 플랫폼의 모든 글을 읽을 수 있다고 전제하지 않는다.

추출 대상은 장소명·지점·주소, 글에서 추천한 메뉴, 가격 언급, 주차·예약·대기 팁이다. 작성자의 경험과 추천을 현재의 확정 정보처럼 표시하지 않고 출처·시점을 함께 보여준다. 여러 장소가 있는 글은 장소별로 나누고, 이미 저장된 가게면 지도 핀을 늘리는 대신 참고 글을 추가한다. 인스타와 블로그의 메뉴·가격 정보가 다르면 각 출처를 확인할 수 있게 한다.

읽을 수 없는 글도 링크는 보관하고 본문·캡처 추가 또는 장소 검색으로 보완한다. 지원 사이트별로 단일 장소, 여러 장소, 사진 중심, 오래된 글, 접근할 수 없는 글을 확인한다. 같은 URL의 재전달, 모바일·공유 URL의 중복, 다른 출처의 동일 지점 연결도 검증한다. 웹에서 읽은 내용은 추출 대상 자료로만 다루고 그 안의 지시문은 실행하지 않도록 설계한다.

**V1.0은 ‘둘이 고르는 경험’을 첫 번째 제품 차별화 가설로 삼는다.**

각 장소에 ‘가고 싶어’, ‘이번 주에’, ‘다음에’를 표시하고 두 사람이 공통으로 선택한 곳을 모아준다. 지역, 예상 예산, 사용할 시간, 실내·실외 조건으로 저장한 장소에서 후보 세 곳 정도를 제시한다. 상세 정보가 없는 조건은 확인 필요로 표시하고, 추천 이유를 짧게 보여준다. 한쪽의 저장 수가 많다고 다른 사람의 선호가 묻히지 않도록 각자의 선택을 확인할 수 있게 한다.

별도 장문의 채팅보다는 장소별 짧은 메모와 후보 비교를 먼저 제공한다. ‘성수에서 3시간, 2인 예산 6만 원’처럼 조건을 주면 둘이 관심 표시한 곳을 우선 확인하고, 선택한 장소를 ‘이번 주 약속’으로 확정한다. 예산 정보가 없으면 AI가 확정값을 만들어 채우지 않는다.

추천 엔진은 우선 공통 관심·거리·카테고리·방문 여부처럼 설명 가능한 기준으로 시작한다. 자연어 입력과 취향 모델은 같은 과제를 더 편하게 해결하는지 확인하고 확장한다.

**V1.5는 실제 방문에 필요한 계획을 지원한다.**

식사 → 카페 → 전시처럼 2~4곳을 묶고 순서 변경·한 장소 교체를 쉽게 한다. 이동 방식, 예상 이동 시간, 머무는 시간, 약속 시각을 반영한다. 이동 시간은 지원 가능한 경로 데이터로 계산하고, 아직 확인하지 못한 구간은 추정임을 표시한다. 영업시간·휴무·행사 기간은 확보된 출처와 확인 시점을 보여주고 원본 확인 경로를 둔다.

팝업·전시는 V0.1부터 ‘놀거리’ 장소로 저장할 수 있다. 이 버전에서는 기간, 예약 링크, 종료 전 알림 등 시간에 따라 달라지는 동작을 보강한다. 비 오는 날 대체 장소, 문을 닫은 곳 교체, 일정 공유·캘린더 추가를 순차적으로 검증한다. 예약은 우선 공식 예약 페이지 연결로 지원하고, 실제 예약·결제 연동은 별도 수요와 연동 가능성이 확인된 뒤 판단한다.

**V2.0은 방문 후의 적은 입력으로 다음 선택을 개선한다.**

방문 완료 시 ‘또 갈래?’, ‘다음에도 주문할 메뉴’, ‘사진 한 장’ 정도로 기록을 끝낼 수 있게 한다. 음식 맛과 공간 분위기는 별도로 남길 수 있고 두 사람의 평가를 각각 유지한다. 기록이 적을 때는 사용자가 직접 선택한 선호를 활용한다.

이후 저장했지만 오래 보지 않은 장소, 이전에 좋아했던 메뉴·분위기와 맞는 장소를 다시 제안한다. 자연어 검색은 ‘네가 저장한 조용한 카페’처럼 실제 저장 데이터로 답할 수 있는 범위부터 제공한다. 새 장소 발견 추천은 저장한 장소의 재발견보다 후순위로 둔다. 선택형 주말 알림과 월별 방문 기록은 반복 이용 효과를 보고 추가한다.

**V3.0은 다른 커플에게 공개할 때 선택하는 확장이다.** 개인용으로 만족한다면 이 단계는 필수가 아니다. 여러 공간·사용자에게 공개하기 전에 권한 분리, 계정·데이터 복구, 지원 문의, 오류 처리와 처리 비용을 점검한다. 분석 남용 방지와 이용 한도는 유료화 전에도 운영에 필요한 시점에 적용한다.

V0.8에서 추가한 블로그 다음으로 유튜브·지도 공유 등 실제 요청이 많은 출처를 늘린다. 수신 경로와 콘텐츠 출처를 독립적으로 확장하며, 각 출처의 실패율·처리 시간·비용을 별도로 확인한다. 해외 장소, 친구 모임, 여행 계획은 각각 새로운 사용자 요구와 운영 부담이 있으므로 한 번에 확장하지 않는다.

유료화는 ‘두 사람이 함께 쓰는 한 요금제’와 ‘분석량 추가 구매’를 비교하는 가설을 제안한다. 기본 공동 저장·조회는 무료 범위로 검토하고, 대량 가져오기·고급 일정·추가 분석량 등의 지불 의사를 확인한다. 정확한 가격은 이용량과 실제 AI·지도·저장 비용을 측정한 뒤 정한다. 원래 기록의 조회·수정·내보내기는 사용자의 신뢰에 직접 영향을 주는 기능으로 취급한다.

**버전을 넘어가는 판단은 사용 과제로 확인한다.** 아래 기준은 실험 설계 제안이며 이미 달성한 결과가 아니다.

| 단계 | 확인할 지표 | 해석 |
|---|---|---|
| 자동 정리 | 제출 링크 중 유용한 카드 완성 비율, 잘못된 지점 수, 근거 없는 메뉴 수, 처리 시간 | 실패를 제외한 정확도만 제시하지 않음. 정확도와 커버리지를 함께 봄 |
| 함께 사용 | 두 사람 모두 저장·선택한 주의 수, 저장한 장소를 다시 연 횟수 | 한 사람이 정리만 하는 도구인지, 둘이 실제 사용하는지 구분 |
| 기억 | 원본 재시청 없이 추천 메뉴·저장 이유를 찾을 수 있는지 | 예쁜 카드가 실제 검색 수고를 줄이는지 확인 |
| 결정 | 동일한 지역·예산 과제에서 장소 확정까지 걸린 시간 | 기존 DM+지도 방식과 같은 조건으로 비교 |
| 계획 | 제안한 코스를 실제 방문에 사용한 비율, 사용자가 수정한 구간 | 거리만 가까운 코스가 아니라 실행 가능한 코스인지 확인 |
| 지속 이용 | 활성화된 커플의 4주 후 공동 사용, 방문 기록과 재추천 수용 | 초기 5~10커플은 방향 확인용이며 시장 전체로 일반화하지 않음 |
| 사업화 | 성공한 저장 1건의 처리 비용, 커플당 월 이용량·운영비, 실제 유료 전환 | 설문상의 구매 의사와 실제 결제를 구분 |

**공개 출시 시점은 버전 번호보다 준비 상태로 정한다.** V0.1부터 비공개 시험 사용은 가능하다. 여러 커플이 가입하는 서비스로 공개할 경우에는 해당 시점부터 이용자 간 데이터 분리, 공유 해제, 탈퇴·삭제, 복구, 오류 대응이 갖춰져야 한다. 이를 V3.0까지 미룬다는 의미가 아니다.

**지금 구체화할 개발 범위는 V0~V0.5를 권한다.** DM으로 인스타 게시물 저장, 기본 메뉴·요약, 둘만의 지도, 이해하기 쉬운 카드와 위치 보정까지가 첫 묶음이다. 블로그를 첫 확장으로 추가할 수 있는 구조를 이때 갖추고, 실제 지원은 V0.8에서 검증·출시한다. V1.0의 후보 선택은 클릭 가능한 화면으로 먼저 검증한다. 전체 여행 예약, 공개 추천 피드, 상점 광고, 개인 DM 전체 자동 수집은 초기 일정에 확정 기능으로 넣지 않는다. 이후에는 실제 사용에서 반복되는 불편을 기준으로 다음 버전의 범위를 조정한다.
